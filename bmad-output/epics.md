## Shared-file conventions (parallel-safety rules for every story)

These rules let stories run in parallel without editing the same files
[Inference, from ADR-038 module boundaries]:

- **Dependencies are declared up front** in Story 1.1 (`backend/pyproject.toml`,
  `frontend/package.json`). Later stories don't edit them. If a missing dependency is
  discovered, it goes in a tiny follow-up story owned by the builder.
- **Routers auto-discovered:** `app/api/router.py` (Story 1.2) imports every
  `app/<module>/routes.py` automatically, so no shared router list is edited.
- **Frontend routes auto-discovered:** `frontend/src/routes/` (Story 1.10) loads feature
  route modules via `import.meta.glob`, so no shared route table is edited.
- **Settings per module:** `app/<module>/settings.py`. `core/config.py` holds only the
  base settings (Story 1.2).
- **Audit events per module:** `app/<module>/audit_events.py`, registered with the
  audit registry (Story 7.1).
- **Readiness checks per module:** each module registers its own `/readyz` check via
  the registry from Story 1.2.
- **Migrations:** one Alembic revision file per story, named
  `migrations/versions/<epic>_<story>_<slug>.py`. Parallel heads are joined with an
  `alembic merge` revision owned by whichever story merges second.
- **Generated API types** (`frontend/src/api/schema.d.ts`) are regenerated by script
  and never hand-edited, so they are not part of any story's scope.
