# 1.11: Jobs queue and worker

**Story ID:** 1.11
**Epic:** 1 — Platform Foundation & Model Selection
**Slug:** jobs-queue-and-worker
**Status:** ready-for-dev

## Story

As the **builder**,
I want **a Postgres-backed job queue, a worker with cron scheduling and a GPU semaphore with per-user fairness**,
so that **ingestion, summaries, applies, lifecycle and audit jobs run reliably outside the request path**.

## Acceptance Criteria

1. Migration `1_11_jobs` creates `jobs` with:
   - `id` uuidv7, `type` text, `user_id` uuid null, `space_id` uuid null, `payload` jsonb, `priority` int (default 100)
   - `status` enum `queued|running|succeeded|failed|cancelled`, `progress` jsonb, `attempts` int, `max_attempts` int (default 3)
   - `run_after`, `lease_until`, `error_code` text null, `correlation_id`, timestamps
   - index on `(status, priority, run_after)`
2. `jobs.registry.register(type, payload_model, handler, llm_heavy=False)` registers a job type. `enqueue(type, payload, *, user_id, space_id, priority)` validates `payload` against that model. Payload models may only use **UUIDs, enums, ints, bools, dates and constrained identifiers**; registering a model with a free-text `str` field raises at import time.
3. The runner claims jobs with `SELECT … FOR UPDATE SKIP LOCKED` ordered by `priority, run_after`, and sets a lease (default 120 s, renewed by heartbeat).
   - Failures retry with exponential backoff up to `max_attempts`, recording only an `error_code`, never the exception message.
   - Jobs whose lease expired while `running` are re-queued on startup and periodically.
4. **GPU fairness for `llm_heavy` types:**
   - a Valkey semaphore limits concurrent heavy jobs (setting, default **2**; TTL-protected against crashed holders);
   - when choosing the next heavy job, the runner picks **round-robin across `user_id`** (oldest job of the user served least recently), not plain FIFO.
5. `jobs.scheduler.register_cron(name, cron_expr, func)` registers cron jobs. `app.worker.main` runs the APScheduler 3.x `AsyncIOScheduler` (timezone `Asia/Kolkata`) alongside the runner, and shuts down gracefully (in-flight jobs finish or release their lease) on SIGTERM.
6. `update_progress(job_id, done, total)` and `get_job_for_owner(job_id, user_id)` (returns nothing unless the user owns the job) are available. The worker exposes `/healthz` on internal port 8081 only, and registers a readiness check.

## Dev Notes

- **Jobs:** a worker process with APScheduler 3.x plus a Postgres `jobs` table polled with
  `FOR UPDATE SKIP LOCKED`; max 3 attempts with backoff; idempotent jobs; no Celery or arq.
  [Source: architecture.md#ADR-017]
- **Payloads hold only IDs and enums (no content).** Job types: `ingest`, `summary`,
  `comparison`, `apply_ops`, `lifecycle`, `audit_verify`, `backup`, `user_purge`.
  [Source: architecture.md#ADR-017] (amendment 2026-10-07)
- **Fairness:** at most 2 LLM-heavy jobs at once, via a Valkey semaphore, round-robin
  across users. Chat requests get higher vLLM priority (handled in the LLM gateway, 1.5).
  [Source: architecture.md#ADR-029]
- Valkey is never the source of truth; the semaphore is advisory with TTL. Job state lives
  in Postgres. [Source: architecture.md#ADR-018]
- No exception messages in logs or the DB (content may leak through parser errors); store
  `error_code` only. [Source: architecture.md#ADR-033]
- The `jobs` table holds no content, so it has no RLS. User-facing reads must go through
  `get_job_for_owner`. [Inference, consistent with ADR-023: RLS applies to content tables]
- The worker has no HTTP API except a health endpoint on an internal port. [Source: architecture.md#4-component-design] [Inference: port 8081]
- Use `app.core.db.transaction()` and `app.core.obs` logging. Settings go in `jobs/settings.py`. [Source: epics.md#shared-file-conventions-parallel-safety-rules-for-every-story]

## Testing

- **Approach:** integration tests with the `pg` and `valkey` fixtures (1.6); time control by injecting a clock.
- **Per-AC verification:**
  - AC #1 → migration up and down.
  - AC #2 → registering a model with `comment: str` raises; enqueue with an invalid payload raises.
  - AC #3 → two concurrent runners never claim the same job; a failing handler retries with backoff and ends `failed` with `error_code`; an expired lease is re-queued.
  - AC #4 → with jobs queued for users A×5 and B×1 and concurrency 1, B's job runs second; never more than N heavy jobs at once.
  - AC #5 → a registered cron fires in a test with a fake clock; SIGTERM leaves no job stuck in `running` without a lease.
  - AC #6 → a non-owner gets nothing; the worker `/healthz` responds on 8081.
- **Fixtures:** dummy job types (`noop`, `fail_twice`, `heavy_sleep`).
- **Edge cases:** Valkey down (heavy jobs pause, the runner keeps light jobs flowing; readiness reports it); a job handler raising an exception with sensitive text (the text must not appear in the DB or logs).

    - Column types, nullability and defaults (`uuidv7()`, priority 100, max_attempts 3, `queued`) are checked.
    - The `job_status` enum labels and the `(status, priority, run_after)` index are checked.
    - `app_rw` can use the table, and RLS is off.
    - Downgrade to `1_2_baseline` drops the table and enum; upgrade restores them.
  - AC #2: registration raises `PayloadModelError` for each content-capable field kind: `comment: str`, optional str, `list[str]`, a nested model with str, `float`, `dict`, `Any`, `bytes`, and a `str` with only a pattern. UUID/enum/Literal/int/bool/date/datetime/`Identifier`/nested models/containers register. An invalid payload raises `InvalidPayloadError` without echoing the value. Unknown types raise. The stored payload is the validated model dump (extra keys dropped).
  - AC #3:
    - **Claiming:** order is priority then run_after, and a future `run_after` isn't claimed. 30 concurrent `claim()` calls on 20 jobs return 20 distinct jobs. Two runners draining 30 jobs run each exactly once.
    - **Retries:** `fail_twice` retries at +10 s and +20 s on a fake clock and succeeds on attempt 3. `always_fail` ends `failed`/`unhandled_exception` after 3 attempts. Its sensitive message (a PAN) is in neither `jobs::text` nor the logs, which keep `exc_type` and location only. `JobError` codes are stored, `PermanentJobError` doesn't retry, malformed codes become `job_error`, and an invalid stored payload fails as `invalid_payload`.
    - **Leases:** an expired lease is re-queued (`lease_expired`) by `reap()` and on runner start-up; on the last attempt it is `failed`. Heartbeats keep a 0.4 s lease alive for a 0.9 s job. A lost lease cancels the handler without touching the new owner's row. Stale-token heartbeat/complete/fail/release are no-ops.
  - AC #4:
    - **Fairness:** A×5 then B×1 at concurrency 1 runs **A, B, A, A, A, A**. A/B/C 3/3/1 runs A, B, C, A, B, A, B. Priority still comes before fairness.
    - **Cap:** 3 runners × concurrency 4 over 12 heavy jobs peak at **2** concurrent, and no slot leaks afterwards.
    - **Semaphore:** limit, release and idempotent re-acquire work; a crashed holder expires after its TTL and can't renew; renewals keep a live holder.
    - **Valkey down:** heavy jobs stay queued, light jobs run, and `/readyz` reports `jobs.valkey`.
  - AC #5: invalid cron expressions and duplicate names raise. With APScheduler's clock patched, `0 2 * * *` is scheduled for 02:00 IST (20:30 UTC), doesn't fire at 01:59:59 and fires once at 02:00:01, and the next run is +1 day. A failing cron logs `cron.failed` without its message. SIGTERM, sent with `os.kill` to the in-process worker, lets a 0.3 s job finish (`succeeded`). It releases a 60 s job after the 0.2 s grace (`queued`, attempts back to 0, handler cancelled). In both cases no row is left `running` or holding a lease.
  - AC #6: the owner gets a `JobView` without the payload. Another user, an unknown id and a system job (no `user_id`) give `None`. Progress set from a handler shows as `{"done": 2, "total": 2}`. Bad progress values raise, and progress on a non-running job is ignored. The worker app serves only `/healthz`, `/readyz` and `/metrics`; the defaults are `127.0.0.1:8081`.
- **Decisions / deviations:**
  - **Extra columns** beyond AC #1:
    - `lease_token` (uuid): a fresh token per claim. Every later write checks it, so a runner that lost its lease can't finish a re-claimed job.
    - `started_at` (the last claim): drives fairness.
    - `finished_at`.
    - `ix_jobs_user_id`, for owner reads.
    - Checks `attempts >= 0` and `max_attempts >= 1`.
    - `correlation_id` is `text` (copied from the enqueuing request's contextvar).
    - No FKs: `users`/`spaces` arrive in 2.1+.
  - **Priority:** lower runs first. Heavy-job order is priority, then the user whose last heavy start is oldest (users never served within a 24 h window go first), then that user's oldest job. Fairness is computed from `jobs.started_at` in the claim query itself (CTE + `FOR UPDATE OF … SKIP LOCKED`), so it is consistent across workers with no extra state.
  - **Attempts:** a reaped (expired) lease counts as an attempt, so a job that crashes its worker ends `failed` rather than looping. A lease released on shutdown does not count.
  - **Semaphore:** a Valkey sorted set scored by expiry, using Lua scripts and the **server** clock (worker clocks don't matter). The heartbeat renews it. The limit is `APP_JOBS_HEAVY_CONCURRENCY` (default 2) and the TTL `APP_JOBS_SEMAPHORE_TTL_S` (90 s). If Valkey errors, `acquire` returns `False`, so heavy jobs pause while light jobs keep flowing.
  - **Payload rule:** `str` is allowed only as `registry.Identifier`, a marker-annotated `str` matching `^[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}$`. A pattern alone doesn't count. `Literal` string values are allowed (code-defined). `float` is rejected: figures don't belong in payloads.
  - **Handler API:** `async def handler(ctx: JobContext, payload: Model)`. `ctx` carries `job_id`, `user_id`, `space_id`, `attempt`, `correlation_id` and `progress(done, total)`. Raise `JobError(code)` or `PermanentJobError(code)` to pick the `error_code`; any other exception is stored as `unhandled_exception`.
  - **Logging:** `job_id` and the job type aren't in obs's allow-list (1.2), so job logs use `module=jobs.<type>` with the job's `correlation_id`, `user_id` and `space_id` bound.
  - **Discovery:** the worker imports every `app/<module>/jobs.py`, where feature stories call `register()` / `register_cron()`. This is the jobs equivalent of the auto-discovered routers, so no shared list is edited.
  - **Settings** (`APP_JOBS_*`): lease 120 s, heartbeat 30 s, reap 30 s, poll 1 s, backoff 10 s × 2ⁿ capped at 600 s, concurrency 4, shutdown grace 20 s, timezone `Asia/Kolkata`, health `127.0.0.1:8081`. The Valkey URL comes from `APP_JOBS_VALKEY_URL` or **`APP_VALKEY_URL`** (default `valkey://valkey:6379/0`). No Valkey URL setting existed before.
  - **Worker:** the health server is a FastAPI app reusing `app.api.health.router`, run by a uvicorn `Server` subclass that skips uvicorn's own signal capture (the worker owns SIGTERM). Crons run with `max_instances=1`, `coalesce=True` and a 5-minute misfire grace.
  - APScheduler 3.x ships no type stubs; its imports carry `# type: ignore[import-untyped]` (pyproject.toml is 1.1 scope).
