# 1.2: Core platform modules

**Story ID:** 1.2
**Epic:** 1 — Platform Foundation & Model Selection
**Slug:** core-platform-modules
**Status:** ready-for-dev

## Story

As the **builder**,
I want **the shared core (settings, DB sessions with RLS context, RFC 9457 errors, IDs, content-free logging, correlation IDs, router auto-discovery, health/readiness)**,
so that **every feature story plugs into one consistent platform without editing shared files**.

## Acceptance Criteria

1. `app.api.app.create_app()` builds the FastAPI app.
   - `app/api/router.py` **auto-discovers** every `app/<module>/routes.py` that exposes `router` and mounts it under `/api/v1`.
   - `/healthz`, `/readyz` and `/metrics` are mounted at root. `app/main.py` exposes `app` for uvicorn.
   - `python -m app.api.export_openapi > openapi.json` writes the OpenAPI document.
2. `app.core.errors` provides `ProblemException(status, code, title, detail=None, **ext)` plus exception handlers.
   - All errors are `application/problem+json` (RFC 9457) with `type`, `title`, `status`, `detail`, `instance`, `code` and `correlation_id`.
   - Pydantic validation errors map to 422 `validation_error` with an `errors` list of field paths only (no input values echoed).
   - Unhandled errors map to 500 `internal_error` with no exception text.
3. Middleware accepts `X-Correlation-ID` when it's a valid UUID, otherwise generates a UUIDv7. It binds the ID to the structlog context and returns it in the response header.
4. `app.core.obs` configures structlog JSON logging with a **field allow-list**: timestamp, level, correlation_id, user_id, space_id, module, event, latency_ms, count fields, status_code, error_code, exc_type, exc_location.
   - Exceptions log **type + module + code location only, never the message**.
   - Request and response bodies are never logged.
   - A `register_scrubber(fn)` hook runs registered scrubbers on every log event before output.
5. `app.core.db` provides an async engine and session factory, plus `async with transaction(context: Mapping[str, str] | None)`. When `context` is given it executes `SELECT set_config('app.user_id', :v, true)` (and `app.grant_id`) at transaction start; when `None` it sets nothing.
6. `app.core.readiness` keeps a registry of named async checks. `/readyz` returns 200 when all pass, or 503 problem `not_ready` listing **only the failing check names**. `/healthz` returns 200 when the process is alive.
7. Alembic is configured for async: `backend/alembic.ini`, `migrations/env.py` (reads the DB URL from settings, uses the `app_migrator` role), and a baseline revision `1_2_baseline` creating extensions `vector` and `citext`. `app.core.events` provides an in-process async hook registry (`subscribe(name, fn)`, `await emit(name, **payload)`).

## Dev Notes

- REST/JSON under `/api/v1`, with OpenAPI as the contract. The frontend generates types
  from it. [Source: architecture.md#ADR-002]
- Error envelope: RFC 9457 with `code` and `correlation_id`. Not accessible = 404, used by
  later stories. [Source: architecture.md#ADR-003]
- Naming: snake_case JSON, `APP_` env prefix, problem codes snake_case. [Source: architecture.md#ADR-004]
- Logging must be content-free: field allow-list, **no exception messages** (parser and DB
  errors can contain document text), no bodies, scrubber as a final net. Span attributes
  are allow-listed too. [Source: architecture.md#ADR-033] [Source: prd.md#NFR-023]
- **RLS context:** later stories set `app.user_id` / `app.grant_id` per transaction.
  Policies return no rows without a context. Use `set_config(name, value, is_local=true)`,
  which equals `SET LOCAL` but accepts bind parameters. [Source: architecture.md#ADR-023] [Inference: set_config form]
- IDs are UUIDv7. DB defaults use `uuidv7()` (PostgreSQL 18); Python-side IDs (e.g.
  correlation IDs) use `uuid_utils.uuid7()`. [Source: architecture.md#ADR-005]
- Settings: pydantic-settings, Compose secrets under `/run/secrets`, never read
  `os.environ` directly outside `core/config.py`. [Source: architecture.md#ADR-021]
- **Auto-discovery and per-module registries avoid shared-file edits** across parallel
  stories (routers, readiness, events). [Source: epics.md#shared-file-conventions-parallel-safety-rules-for-every-story]
- Migrations run as `app_migrator`; the app runs as `app_rw`. Roles are created by the
  Postgres init script in Story 1.3. [Source: architecture.md#ADR-005]
- Readiness: later modules register checks (vLLM chat and guard, parser, KEK loaded). A
  failing safety dependency makes the system refuse work. [Source: architecture.md#ADR-033] [Source: prd.md#NFR-013]

## Testing

- **Approach:** unit tests with FastAPI's `TestClient` or httpx `AsyncClient`. The DB
  helper test uses the Postgres fixture from Story 1.6 if available; otherwise mark it
  `@pytest.mark.db` and run it once 1.6 lands.
- **Per-AC verification:**
  - AC #1 → a temporary test package `app/_testmod/routes.py` is auto-mounted at `/api/v1/...`; `export_openapi` emits valid JSON.
  - AC #2 → raised `ProblemException` and a validation error produce exact problem bodies; an unhandled `ValueError("secret text")` returns 500 **without** "secret text" in the body or the logs.
  - AC #3 → a supplied valid ID is echoed; an invalid one is replaced by a UUIDv7.
  - AC #4 → a log event with a disallowed field (e.g. `prompt=`) has that field dropped; an exception log contains `exc_type` but not the message; a registered scrubber runs.
  - AC #5 → inside `transaction({"app.user_id": X})`, `current_setting('app.user_id', true)` returns X; after commit it's unset.
  - AC #6 → a failing registered check yields 503 with only its name.
  - AC #7 → `alembic upgrade head` on an empty DB creates the extensions; emitting an event calls its subscribers.
- **Fixtures/mocks:** a dummy readiness check; a dummy routes module.
- **Edge cases:** correlation header with injection characters; a readiness check that raises (counts as failing, name only); nested `transaction` calls (document as not supported, raise a clear error).
