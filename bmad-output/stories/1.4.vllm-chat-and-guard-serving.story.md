# 1.4: vLLM chat and guard serving

**Story ID:** 1.4
**Epic:** 1 — Platform Foundation & Model Selection
**Slug:** vllm-chat-and-guard-serving
**Status:** ready-for-dev

## Story

As the **builder**,
I want **the chat model and the guard model served by vLLM on the A10, loaded offline and reachable only on the internal network**,
so that **the app has self-hosted inference with no data leaving the VM**.

## Acceptance Criteria

1. `deploy/compose.inference.yml` defines `vllm-chat` and `vllm-guard`:
   - pinned `vllm/vllm-openai:<tag>` image, NVIDIA GPU reservation
   - attached **only** to the `inference` network, **no published ports**
   - models mounted read-only from `/data/models`; `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`
2. Launch arguments come from env files (`deploy/vllm/chat.env`, `guard.env`), so changing model or limits is configuration only.
   - **chat:** `--served-model-name chat`, `--gpu-memory-utilization 0.78`, `--max-model-len 16384`, `--kv-cache-dtype fp8`, `--enable-prefix-caching`, `--max-num-seqs 16`, `--enable-auto-tool-choice --tool-call-parser hermes`
   - **guard:** `--served-model-name guard`, `--gpu-memory-utilization 0.12`, `--max-model-len 4096`
   - defaults: chat `Qwen3-14B` INT4 (AWQ), guard `Qwen3Guard-Gen-0.6B`
3. Both containers become healthy (`/health`) on the A10-24Q at the same time without out-of-memory errors. `nvidia-smi` memory use after warm-up is recorded in `deploy/vllm/README.md`.
4. `deploy/models/stage-models.sh` installs model directories from an approved transfer location into `/data/models`. It verifies every file against `deploy/models/manifest.yaml` (SHA-256) and **refuses to install on any mismatch**. The README documents the one-time controlled download done outside the VM.
5. `deploy/vllm/smoke.sh`, run from a container on the `inference` network, performs:
   - list models
   - a chat completion
   - a streamed completion
   - a tool-call request
   - a structured (`json_schema`) request
   - a guard classification
   - a request containing `cache_salt` and `priority`

   For the last one it **records whether each field is honoured or rejected** by the pinned version (input to 1.9 and ADR-029/031 fallbacks).

## Dev Notes

- **Two vLLM OpenAI-compatible servers on the A10:**
  - chat (default Qwen3-14B AWQ/GPTQ INT4): 0.78 GPU memory, max-model-len 16384, fp8 KV cache, prefix caching, max-num-seqs 16, auto tool choice with the hermes parser;
  - guard (Qwen3Guard-Gen-0.6B): 0.12, 4096.

  Weights are pre-downloaded; containers run offline on an internal network.
  [Source: architecture.md#ADR-009]
- **Host:** Azure VM `nbfcuatyolomlapp01`, GPU **A10-24Q** (24 GB vGPU), driver 570.211,
  CUDA 12.8. Ampere: INT4 via Marlin, no native FP8 compute; FP8 KV cache is allowed.
  [Source: decision-log.md#2026-10-07--host-specs-verified-nbfcuatyolomlapp01] [Source: research-report.md#finding-2]
- **Store models on `/data/models`** (persistent), never on `/mnt` (ephemeral) or the
  small root disk. [Source: architecture.md#ADR-034] [Source: architecture.md#ADR-028]
- **Zero egress:** no runtime downloads; updates follow the offline procedure with
  checksums. [Source: architecture.md#ADR-034]
- Qwen3 tool calling uses the `hermes` parser. Thinking mode is disabled per request by
  the gateway, because of known reasoning/tool-parser issues. [Source: research-report.md#finding-2] [Source: architecture.md#ADR-009]
- **`cache_salt` support must be confirmed;** if unsupported, disable prefix caching
  rather than share it. **Priority scheduling** (`--scheduling-policy priority`) is used
  if supported; otherwise a queue-depth pause applies in summary jobs. [Source: architecture.md#ADR-031] [Source: architecture.md#ADR-029]
- **vGPU:** a Q-profile vGPU supports CUDA compute. Confirm no vGPU licensing throttling
  appears under sustained load (note it in the README). [Inference]
- gpt-oss-20b is risky on Ampere (MXFP4 Hopper-only, fallback kernel issues); don't use
  it as the default. [Source: research-report.md#finding-2]

- **Decisions / deviations:**
  - **Image `vllm/vllm-openai:v0.31.0-cu129`:** the default `v0.31.0` image is CUDA 13.0 (driver ≥ 580). The VM has driver 570 (CUDA 12.8), which runs CUDA 12.9 builds through minor-version compatibility. **This must be confirmed on UAT.** The fallback is in the README: a newer driver from IT, or an older vLLM with a CUDA 12.8 image. No `cu128` tags exist for recent releases.
  - **`--scheduling-policy priority`** is added to the chat flags (ADR-029), so `priority` is accepted. Remove it if the smoke test reports problems.
  - **`--max-num-seqs 16`** is added for guard, to keep its CUDA-graph and KV footprint inside the 0.12 share.
  - **Start order:** `vllm-guard` `depends_on: vllm-chat (service_healthy)`, covering the "guard claims more than its share" edge case.
  - **Telemetry off:** `VLLM_NO_USAGE_STATS=1`, `VLLM_DO_NOT_TRACK=1`, `DO_NOT_TRACK=1`. Request logging stays off (vLLM's default `enable_log_requests=False`).
  - **Hardening:** `cap_drop: ALL` and `no-new-privileges`. Persistent compile caches in `/data/vllm-cache/{chat,guard}` (`/root/.cache`). `shm_size: 4gb`. Healthcheck `/health` via python3, with a 900 s start period.
  - **`compose.inference.yml` redeclares** `networks: inference: internal: true`, identical to `compose.yml`. Compose merges them, and `docker compose config` is clean.
  - **`cache_salt` check:** "honoured" is measured, not assumed. The smoke test reads `vllm:prefix_cache_hits` and expects hits for a repeated prompt with the same salt only (0 for another salt, 0 unsalted).
  - **`smoke.sh`** runs in a throwaway `invest-ai-llm/backend` container (Python + httpx) attached only to `invest-ai-llm_inference`. It prints host `nvidia-smi` memory when available.
  - **`stage-models.sh`** uses host `python3` (stdlib only), with a parser for the fixed manifest layout; there is no PyYAML on the host.
