# 1.5: LLM gateway

**Story ID:** 1.5
**Epic:** 1 — Platform Foundation & Model Selection
**Slug:** llm-gateway
**Status:** ready-for-dev

## Story

As the **builder**,
I want **a single gateway module that is the only code talking to vLLM, enforcing per-user cache salts, priorities, timeouts and model profiles**,
so that **models can be swapped by configuration and no user's prompts can warm or leak through another user's cache**.

## Acceptance Criteria

1. `app.llm.gateway` is the only module calling model servers. It exposes async `stream_chat(...)`, `chat_completion(...)`, `structured(..., schema)` (OpenAI `response_format` `json_schema`) and `guard_classify(text, kind: prompt|response) -> GuardVerdict(safety: safe|unsafe|controversial, categories: set[str])`.
2. **Every call requires `salt_subject` (a user ID).** The gateway sends `cache_salt = base64url(HMAC-SHA256(salt_secret, salt_subject))`. Calls without it raise `MissingCacheSalt`; only `health()` is exempt. If the profile says `supports_cache_salt: false`, the gateway **refuses to start** unless `APP_LLM_PREFIX_CACHING_DISABLED=true` acknowledges that prefix caching is off on the server.
3. **Priority:** callers pass `RequestPriority.CHAT` or `.BACKGROUND`. When the profile says `supports_priority`, the gateway sends `priority` (CHAT=0, BACKGROUND=10); otherwise it omits the field.
4. **Profiles** in `llm/profiles.yaml` map logical names `chat` and `guard` to `base_url`, served model name, `extra_body` (chat includes `chat_template_kwargs: {enable_thinking: false}`), `max_tokens` defaults and capability flags. Switching models is a config change only.
5. **Timeouts and errors:** connect 2 s; guard total 3 s; chat first token 10 s, then 60 s total. One retry on connection errors only, never on content. Typed errors `LLMUnavailable` and `LLMTimeout` let callers fail closed. Readiness checks for `chat` and `guard` are registered.
6. **Telemetry:** one OTel span per call with allow-listed attributes only (logical model, served model, priority, latency, prompt/completion token counts, outcome). No prompt or response text in spans or logs.
7. `pydantic_ai_model(salt_subject, priority)` returns a PydanticAI `OpenAIModel` (via `OpenAIProvider` with the gateway's configured `AsyncOpenAI` client) plus matching `model_settings` (`extra_body` with salt, priority and thinking flag), so `assistant` (3.3) never constructs clients itself.

## Dev Notes

- **The `llm` module is the only client of the vLLM servers.** No model names are
  hard-coded; profiles come from config. Thinking mode is off. Timeouts are connect 2 s,
  guard 3 s, chat first token 10 s then 60 s, with one retry on connection errors only.
  [Source: architecture.md#ADR-009]
- **Per-user `cache_salt`** = `base64url(HMAC-SHA256(salt_secret, user_id))` on every
  chat and guard request. Background jobs use the job owner's salt. The gateway refuses
  requests without a salt (except health). If the vLLM version doesn't support salts,
  **disable prefix caching**. [Source: architecture.md#ADR-031] [Source: prd.md#FR-041]
- **Priority:** chat requests get higher priority than background jobs. [Source: architecture.md#ADR-029]
- **Fail closed:** callers (guardrails) turn `LLMUnavailable`/`LLMTimeout` into refusals.
  [Source: architecture.md#ADR-024] [Source: prd.md#NFR-013]
- **Guard output parsing:** Qwen3Guard-Gen emits `Safety: ...` and `Categories: ...`;
  unknown output means `controversial` + category `parse_error` (callers treat it as not
  safe). [Source: architecture.md#ADR-024] [Inference: parse-failure handling]
- Spans and logs are content-free (allow-listed attributes). [Source: architecture.md#ADR-033]
- Import rules: only `app.llm` imports `openai` directly; `assistant` gets models through
  this factory. [Source: architecture.md#ADR-038]
- Swappable model by configuration only (NFR-015). [Source: prd.md#NFR-015]

## Testing

- **Approach:** integration tests against the fake LLM (1.6); one optional `@pytest.mark.gpu` test hitting the real vLLM on UAT.
- **Per-AC verification:**
  - AC #1 → each function works with the matching fake scenario; `guard_classify` parses safe, unsafe and garbage.
  - AC #2 → the recorded request has the expected `cache_salt` for user A; a different user gives a different salt; no salt raises; the startup guard behaves per flag.
  - AC #3 → priority present or absent per capability flag.
  - AC #4 → swapping profile YAML changes the served model name in recorded requests.
  - AC #5 → a delay scenario triggers `LLMTimeout` at the right threshold; a connection-refused call retries once, then `LLMUnavailable`; readiness fails when the fake is down.
  - AC #6 → captured spans and logs contain no planted prompt canary.
  - AC #7 → a PydanticAI agent run through the factory produces requests with salt and thinking flag.
- **Fixtures:** `fake_llm` scenarios; canary string `CANARY-LLM-123`.
- **Edge cases:** stream interrupted mid-way (raise a typed error, partial text discarded by the caller); a structured response that fails schema validation (raise `LLMSchemaError`).

- **Decisions / deviations:**
  - **`OpenAIChatModel` instead of `OpenAIModel`:** pydantic-ai 2.54 has no `OpenAIModel`; `OpenAIChatModel` is its successor, used via `OpenAIProvider(openai_client=...)`. The factory returns `(OpenAIChatModel, OpenAIChatModelSettings)`. The settings carry `extra_body` (salt, priority, thinking off), `max_tokens` and `timeout`; PydanticAI sends `max_completion_tokens`, which vLLM accepts.
  - **Signature choices:**
    - `salt_subject` is keyword-only and defaults to `None`, so omitting it raises `MissingCacheSalt` (as the AC says) rather than a `TypeError`.
    - `priority` is required (no default), so background callers cannot silently get CHAT priority.
    - `guard_classify(text, kind, *, salt_subject, priority, prompt=None)`: `prompt` is optional context for response moderation, sent as the user turn.
  - **`stream_chat` is a plain method returning an async iterator,** so salt validation fails at the call, not at first iteration. It yields `TextDelta` events, then one `StreamEnd` (finish reason, assembled tool calls, usage).
  - **`structured` takes a pydantic model class** and returns a validated instance. The ValidationError, which quotes the output, is dropped (`from None`) when raising `LLMSchemaError`.
  - **Timeouts are profile fields** (defaults are the ADR values). Non-streaming chat has only the total deadline, because the first token can't be observed. Timeouts are never retried; only `APIConnectionError` is, once.
  - **Mid-stream transport errors:** openai 3.x is built on `httpx2` and wraps them as `APIConnectionError`. They are mapped to `LLMStreamInterrupted` (a subclass of `LLMUnavailable`) and not retried. A stream that ends without a finish reason is also treated as interrupted.
  - **Error hierarchy:** `LLMError` is the base, with `LLMUnavailable` (`LLMStreamInterrupted`), `LLMTimeout`, `LLMRequestError` and `LLMSchemaError`. `MissingCacheSalt` is a `ValueError` and `LLMConfigError` a `RuntimeError`, so neither is swallowed into a refusal.
  - **Spans are started without being made current** (safe across stream yields). Each call also writes one content-free log line `llm.<operation>`. Attribute names use `_` (e.g. `llm_model`) and are allow-listed through `obs.allow_span_attributes`.
  - **Settings:** `APP_LLM_PROFILES_PATH`, `APP_LLM_BASE_URLS` (JSON), `APP_LLM_PREFIX_CACHING_DISABLED`. The salt secret comes from `/run/secrets/cache_salt_secret` or `APP_LLM_CACHE_SALT_SECRET`, and must be at least 32 characters.
  - The salt is unpadded base64url (43 chars).
  - `profiles.yaml` is parsed with PyYAML, which is shipped through `uvicorn[standard]`; pyproject is not edited.
  - **Guard profile:** `supports_priority: false` (vllm-guard runs FCFS), temperature 0, max_tokens 32. Category labels are kept as emitted; `None` means no categories.
