# 1.6: Fake LLM server and test harness

**Story ID:** 1.6
**Epic:** 1 — Platform Foundation & Model Selection
**Slug:** fake-llm-and-test-harness
**Status:** ready-for-dev

## Story

As the **builder**,
I want **a scriptable OpenAI-compatible fake LLM and shared pytest fixtures for Postgres (with RLS-relevant roles) and Valkey**,
so that **every backend story has deterministic integration tests without a GPU**.

## Acceptance Criteria

1. `tests/fakes/fake_llm/server.py` is an OpenAI-compatible fake that implements:
   - `GET /v1/models`, `GET /health`
   - `POST /v1/chat/completions` with non-streaming and **SSE streaming** responses, **tool calls** (OpenAI `tool_calls` format, streamed as deltas too) and **structured output** (`response_format: {type: json_schema}` returns schema-valid JSON from the scenario)
2. Responses come from a **scenario registry**:
   - a scenario matches by an explicit `X-Fake-Scenario` header, by `model` name, or by a regex on the last user message;
   - a scenario can return text, a sequence of tool calls followed by text, JSON, a delay (to test timeouts) or an HTTP error;
   - the fake records every received request body, including `cache_salt`, `priority` and `extra_body` fields, for assertions.
3. **Guard emulation:** requests to model `guard` return Qwen3Guard-style text (`Safety: Safe|Unsafe|Controversial` + `Categories: ...`) according to the scenario.
4. `backend/tests/conftest.py` provides fixtures:
   - `pg` (PostgreSQL 18 + pgvector from `deploy/compose.test.yml`, migrated to head as `app_migrator`; the app session connects as **`app_rw`**)
   - `valkey`
   - `fake_llm` (in-process uvicorn on a free port with a scenario API: `fake_llm.add(...)`, `fake_llm.requests`)
   - `app_client` (httpx `AsyncClient` against `create_app()` with settings pointing at `fake_llm`)
   - test isolation: tables truncated between tests via `app_migrator`
5. `deploy/compose.test.yml` starts Postgres and Valkey on loopback-only ephemeral ports for local and CI runs. Example tests show a streaming scenario, a tool-call scenario and a guard scenario.

## Dev Notes

- Integration tests use a **fake OpenAI-compatible LLM server** with scripted streams and
  tool calls, against real Postgres and Valkey **with RLS enabled**. [Source: architecture.md#ADR-037] [Source: architecture.md#ADR-022]
- The real gateway sends `cache_salt` on every request (except health checks) and a
  `priority`. The fake must accept and record them so Story 1.5 can assert this. [Source: architecture.md#ADR-031] [Source: architecture.md#ADR-029]
- Chat requests include `chat_template_kwargs: {"enable_thinking": false}` in `extra_body`;
  the fake ignores but records them. [Source: architecture.md#ADR-009]
- Structured outputs (`json_schema`) are used by the scope router and summary map steps. [Source: architecture.md#ADR-024] [Source: architecture.md#ADR-029]
- The guard output format is Qwen3Guard-Gen's: `Safety:` and `Categories:` lines. [Source: architecture.md#ADR-024] [Inference: exact category labels configurable per scenario]
- The app connects as `app_rw` (subject to RLS); migrations and truncation run as
  `app_migrator`. Tests must not use a superuser for app sessions, or RLS tests would pass
  falsely. [Source: architecture.md#ADR-023]
- Per-module fixtures go in `tests/<module>/conftest.py`; this root conftest stays generic. [Source: epics.md#shared-file-conventions-parallel-safety-rules-for-every-story]

## Testing

- **Approach:** self-tests of the harness.
- **Per-AC verification:**
  - AC #1 → the `openai` SDK client consumes non-stream, stream, tool-call and json_schema scenarios without errors.
  - AC #2 → header, model and regex matching; recorded `cache_salt` and `priority` visible.
  - AC #3 → a guard scenario returns the expected lines.
  - AC #4 → `app_client` GET `/healthz` returns 200; `pg` session `current_user` is `app_rw`; data from one test is absent in the next.
  - AC #5 → `docker compose -f deploy/compose.test.yml up` binds only 127.0.0.1.
- **Fixtures:** the scenarios themselves.
- **Edge cases:** streaming tool-call argument chunks split across deltas; client disconnect mid-stream (the fake stops cleanly); a delay scenario exceeding the client timeout.
