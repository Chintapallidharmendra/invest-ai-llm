# 1.7: Synthetic confidential corpus

**Story ID:** 1.7
**Epic:** 1 — Platform Foundation & Model Selection
**Slug:** synthetic-confidential-corpus
**Status:** ready-for-dev

## Story

As the **builder**,
I want **a deterministic, fabricated set of deal-style documents and workbooks with planted identifiers, injections and canaries**,
so that **every test, eval and the UAT environment run without any real deal material**.

## Acceptance Criteria

1. `make corpus` runs seeded generators in `evals/corpus/generate/` and writes byte-stable outputs to `evals/corpus/build/` (git-ignored). Two runs produce identical SHA-256 hashes, which are recorded in `manifest.yaml`.
2. The corpus contains at least:
   - **3 CIMs** (PDF; 60, 110 and 150 pages) with headings, multi-page financial tables and a projections section
   - a **term sheet v3 and v4** (DOCX) with a documented list of ≥ 12 differences (added, removed and changed clauses and figures)
   - an **SPA** (DOCX, ~40 pages)
   - a **pitch deck** (PPTX, 25 slides with speaker notes)
   - **3 financial workbooks** (XLSX: multi-sheet P&L, segment and KPI sheets; one sheet with ≥ 50,000 rows; formulas with cached values; one formula cell **without** a cached value; one hidden sheet)
   - **1 CSV**
   - **2 scanned PDFs** (image-only pages, for OCR)
3. `manifest.yaml` records every planted item with an exact locator (`p.N`, `slide N`, `Sheet!A1`), type and expected handling:
   - **high-risk identifiers**: every FR-012 type and format variant, incl. partial Aadhaar; ≥ 60 instances
   - **benign look-alikes**: CIN, LLPIN, company GSTIN (which embeds a PAN-like substring), ISIN, phone and email of business contacts; ≥ 40
   - **injections**: white text, tiny text, DOCX comment, PPTX speaker note, XLSX cell comment, document metadata, hidden sheet; ≥ 20
   - **canaries**: one unique random token per document
4. `manifest.yaml` also records **reference facts** per document for evals: key terms, ≥ 15 figures with locators per CIM, the term-sheet difference list and workbook totals. These must match the generated content (a self-check script verifies it).
5. All people, companies and deals are fabricated (faker with a fixed seed + hand-written templates). `evals/corpus/README.md` states that **real deal documents must never be added**. `check_corpus.py` fails if any file in `build/` is missing from the manifest.

## Testing

- **Approach:** script-level tests in `evals/corpus/tests/`.
- **Per-AC verification:**
  - AC #1 → generate twice and compare hashes.
  - AC #2 → count files by type, page/slide/row counts.
  - AC #3 → for every manifest item, open the file and assert the value exists at the locator.
  - AC #4 → the self-check recomputes workbook totals and compares to the manifest.
  - AC #5 → add a stray file to `build/` and expect `check_corpus.py` to fail.
- **Fixtures:** none (self-generating).
- **Edge cases:** GSTIN containing a PAN-like substring (must be listed as benign); identifiers split across a line break (list as positive with locator); non-ASCII rupee symbol in tables.
