# 1.8: Eval harness and eval set

**Story ID:** 1.8
**Epic:** 1 — Platform Foundation & Model Selection
**Slug:** eval-harness-and-eval-set
**Status:** ready-for-dev

## Story

As the **builder**,
I want **an evaluation runner and ≥ 80 cases over the synthetic corpus**,
so that **model, prompt and feature changes are measured against the PRD's quality gates instead of guessed**.

## Acceptance Criteria

1. A case schema (YAML, validated by Pydantic in `evals/runner/schema.py`) supports:
   - `id`, `category` (`qa | summary | comparison | table_extract | excel_query | excel_op | not_found | multi_turn | concept | scope_decline`)
   - `documents` (corpus IDs), `turns` (user messages), `summary_template?`
   - `expectations`: `must_cite` (document + locator), `must_contain_figures`, `must_not_contain`, `expect_decline` (category), `expect_not_found`, `rubric` (ref), `reference_output` (path for Excel/table cases)
2. `evals/cases/eval/` contains **≥ 80 cases**: qa ≥ 20, summary ≥ 12, comparison ≥ 6, table_extract ≥ 8, excel_query ≥ 10, excel_op ≥ 10, not_found ≥ 6, multi_turn ≥ 6, concept ≥ 2. All facts are taken from the corpus manifest reference facts (1.7).
3. Runner `python -m evals.runner run --mode api|model --cases <glob> --target <url>`:
   - **`api` mode** drives the deployed app over its HTTP API: login as an eval user, create a space, upload, wait for ready, set the selected set, POST chat and parse SSE, poll jobs, download outputs. It follows the documented API contract. Cases whose endpoint returns 404/501 are reported `skipped: feature-unavailable`.
   - **`model` mode** sends prompts with inlined masked document excerpts directly to an OpenAI-compatible endpoint, for the model spike (1.9).
4. **Scoring:**
   - deterministic checks: citation present and locator correct; figures exact (via the grounding library, 4.4, when available, else exact string); decline category; not-found phrasing; reference-output comparison for Excel (cell-by-cell);
   - summaries scored 1–5 per `evals/rubrics/summary.yaml` (coverage, accuracy, citations) by an LLM judge on the local model, with a human-override file `overrides.yaml`.
5. Reports go to `evals/reports/<timestamp>/` (git-ignored) as `report.md` + `results.json`, with the pass rate per category and overall, and a comparison against PRD thresholds (overall ≥ 85%, summaries ≥ 4/5 for ≥ 85%, 0 ungrounded figures, 100% Excel reference match). The exit code is non-zero if a configured gate fails.

## Dev Notes

- **Eval suite:** ≥ 80 tasks across Q&A, summaries (rubric), comparison, table extraction,
  Excel operations and "not found". Targets: ≥ 85% pass, 100% figures grounded, 100%
  operation matches. [Source: prd.md#NFR-010] [Source: addendum.md#test-suites-release-gates]
- **Summary templates and rubric dimensions** (executive, key terms, financial
  highlights, risks, custom; coverage, accuracy, citations). [Source: addendum.md#fr-046-summary-templates] [Source: prd.md#FR-046]
- **Synthetic corpus only;** eval reports are files, never Langfuse, and never production
  content. [Source: architecture.md#ADR-033] [Source: architecture.md#ADR-037]
- **API contract** the API-mode client targets:
  - `POST /api/v1/auth/login`, `GET /api/v1/spaces`, `POST /api/v1/spaces/{id}/documents`, `GET /api/v1/documents/{id}`
  - `POST /api/v1/conversations`, `PUT /api/v1/conversations/{id}/documents`, `POST /api/v1/conversations/{id}/messages` (SSE)
  - `GET /api/v1/jobs/{id}`, `POST /api/v1/operation-previews/{id}/applications`, `POST /api/v1/outputs/{id}/download-links`

  [Source: architecture.md#6-api-specifications]
- **SSE events** to parse: `meta`, `status`, `delta`, `table`, `sources`, `replace`, `plan`,
  `job`, `done`, `error`; citations come in `sources` items `{kind, document_id, locator}`.
  [Source: architecture.md#ADR-025]
- **Model-mode inputs must use masked text** (apply `guardrails.identifiers.mask` from 4.1
  when available), so even the spike never sends raw planted IDs.
  [Source: architecture.md#ADR-027] [Inference: apply to spike for consistency]
- An LLM judge on the same model is biased. Record judge model and version in reports and
  allow human overrides. [Inference]

## Testing

- **Approach:** unit tests for the schema, scorers and SSE parser; a dry run of all cases in model mode against the fake LLM (1.6) to validate plumbing.
- **Per-AC verification:**
  - AC #1 → invalid cases are rejected with clear errors.
  - AC #2 → a count-per-category script.
  - AC #3 → API mode against a stub server returning 404 marks cases skipped; model mode against the fake LLM completes.
  - AC #4 → a correct/incorrect citation fixture, a figure mismatch fixture, an Excel reference mismatch.
  - AC #5 → the report contains per-category rates; the gate failure exit code.
- **Fixtures:** corpus manifest; fake LLM scenarios; stub API server.
- **Edge cases:** an SSE `replace` event (score the final text); a `done{finish_reason: withheld}` (counts as fail unless decline expected); job timeouts.
