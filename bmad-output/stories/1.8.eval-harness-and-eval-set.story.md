# 1.8: Eval harness and eval set

**Story ID:** 1.8
**Epic:** 1 — Platform Foundation & Model Selection
**Slug:** eval-harness-and-eval-set
**Status:** ready-for-dev

## Story

As the **builder**,
I want **an evaluation runner and ≥ 80 cases over the synthetic corpus**,
so that **model, prompt and feature changes are measured against the PRD's quality gates instead of guessed**.

## Acceptance Criteria

1. A case schema (YAML, validated by Pydantic in `evals/runner/schema.py`) supports:
   - `id`, `category` (`qa | summary | comparison | table_extract | excel_query | excel_op | not_found | multi_turn | concept | scope_decline`)
   - `documents` (corpus IDs), `turns` (user messages), `summary_template?`
   - `expectations`: `must_cite` (document + locator), `must_contain_figures`, `must_not_contain`, `expect_decline` (category), `expect_not_found`, `rubric` (ref), `reference_output` (path for Excel/table cases)
2. `evals/cases/eval/` contains **≥ 80 cases**: qa ≥ 20, summary ≥ 12, comparison ≥ 6, table_extract ≥ 8, excel_query ≥ 10, excel_op ≥ 10, not_found ≥ 6, multi_turn ≥ 6, concept ≥ 2. All facts are taken from the corpus manifest reference facts (1.7).
3. Runner `python -m evals.runner run --mode api|model --cases <glob> --target <url>`:
   - **`api` mode** drives the deployed app over its HTTP API: login as an eval user, create a space, upload, wait for ready, set the selected set, POST chat and parse SSE, poll jobs, download outputs. It follows the documented API contract. Cases whose endpoint returns 404/501 are reported `skipped: feature-unavailable`.
   - **`model` mode** sends prompts with inlined masked document excerpts directly to an OpenAI-compatible endpoint, for the model spike (1.9).
4. **Scoring:**
   - deterministic checks: citation present and locator correct; figures exact (via the grounding library, 4.4, when available, else exact string); decline category; not-found phrasing; reference-output comparison for Excel (cell-by-cell);
   - summaries scored 1–5 per `evals/rubrics/summary.yaml` (coverage, accuracy, citations) by an LLM judge on the local model, with a human-override file `overrides.yaml`.
5. Reports go to `evals/reports/<timestamp>/` (git-ignored) as `report.md` + `results.json`, with the pass rate per category and overall, and a comparison against PRD thresholds (overall ≥ 85%, summaries ≥ 4/5 for ≥ 85%, 0 ungrounded figures, 100% Excel reference match). The exit code is non-zero if a configured gate fails.

- **Decisions / deviations:**
  - **Cases are generated, not hand-typed.** `evals/runner/authoring.py` builds them from the manifest's figures, key terms, term-sheet differences and workbook totals. It finds citation pages and reference outputs in the generated files, and the output is committed and deterministic. Regenerate with `python -m evals.runner author` after a corpus change.
  - **Schema additions beyond the AC list:**
    - `Citation.also`: equally valid locators, e.g. a figure on both the summary page and the P&L table page.
    - `Expectations.must_contain` (phrases) and `reference_ordered`.
    - `Case.modes`: model-mode-impossible cases are `[api]`: the 50k-row sheet, multi-page tables, 110/150-page CIM summaries.
    - `Case.sheet`.
    - excel_query may use `must_contain_figures` instead of a reference CSV.
  - **Reference CSVs carry their printed precision** ("373.0", not "373"). Numbers are compared to within half a unit of the last printed decimal; strings are case- and whitespace-insensitive. Column matching is by normalised header name, falling back to position for same-shape tables. Outputs are preferred to engine tables, and engine tables to tables parsed from text.
  - **Model mode:**
    - Excerpts are the cited units, then units holding expected figures, then the start of each document, within 24,000 chars. This measures reading, citing and refusing, not retrieval.
    - The prompt asks for `[file#locator]` citations, the FR-030 phrase, `DECLINED (<category>):` for out-of-scope requests, and Markdown tables.
    - Masking uses `app.guardrails.identifiers.mask` (4.1) when importable, else the manifest's planted values, applied to excerpt text, locators, turns and judge input.
  - **Figures:** `app.guardrails.grounding` (4.4) when importable. The fallback is an exact string match after whitespace and currency-marker normalisation. "Ungrounded figures" in the fallback are numbers absent from the case's documents, turns, engine tables and reference outputs, at display precision; years, plain counts ≤ 12 and citation text are exempt. The method used is recorded in each report.
  - **Judge:** structured 1–5 scores for coverage, accuracy and citations against the manifest's reference facts; the mean must be ≥ 4. It defaults to the target model in model mode and needs `--judge-url` in API mode. The judge model and URL are written to every report. A summary with neither a judge score nor an override is `needs_review` and counts as not passed.
  - **API mode** follows architecture §6 / ADR-003 / ADR-025. Shapes the contract leaves open are read tolerantly and isolated in `ApiTarget._job_outcome`:
    - job result `output_id`;
    - terminal job statuses `succeeded|completed|done`;
    - conversation `messages[]`;
    - login body `{username, password}`;
    - download link `{url|token}`.
  - **Decline categories** `investment_advice` / `off_topic` are placeholders until Story 4.9 defines the taxonomy.
  - **Layout:** `evals` is used as a namespace package from the repo root (`python -m evals.runner`); `evals/__init__.py` is outside this story's scope. Scoped `ruff.toml` files in `evals/runner/` and `evals/tests/runner/` extend the backend rules.
