## Story

As the **builder**,
I want **the shortlisted chat models measured on the A10 against our own tasks and load**,
so that **the model choice and the † thresholds rest on evidence, not on model cards**.

## Acceptance Criteria

1. **Candidates**, each served by the pinned vLLM image with the guard model co-resident (0.78 / 0.12 split):
   - `Qwen3-14B-AWQ` (primary)
   - `Qwen3-8B-AWQ` (fallback)
   - `Qwen2.5-14B-Instruct` INT4
   - `gpt-oss-20b`, only if it starts on Ampere

   Every candidate is staged offline from `deploy/models/manifest.yaml` with checksums. One that fails to start is recorded as such.
2. **Quality:** `python -m evals.runner run --mode model` on the full eval set gives per-category pass rates for each candidate (Q&A, summary rubric, comparison, table, Excel-op mapping, concept). Tool-call accuracy is scored on ≥ 30 finance prompts with the ADR-026 tool schemas, by valid call, right tool and right arguments.
3. **Performance at 1, 5 and 10 concurrent streams:**
   - TTFT p50/p95 and tokens/s per stream;
   - summary map-call throughput, with chat running alongside;
   - GPU memory headroom;
   - a **30-minute soak** with 10 chats + 2 background summary loops, with 0 OOMs and 0 errors.
4. **Platform features:**
   - whether the pinned vLLM version honours `cache_salt` (different salts → no shared prefix-cache hits; same salt → hits) and `priority` scheduling;
   - that thinking mode stays off via the profile;
   - the hermes tool parser works.
5. **Decision:**
   - a dated `decision-log.md` entry (model, quantisation, vLLM tag, context length, max sequences);
   - the † NFR thresholds confirmed or proposed for change, with numbers;
   - `deploy/vllm/chat.env` and `backend/app/llm/profiles.yaml` updated to the choice;
   - the full report committed at `evals/spike/REPORT.md` (tables + raw `results.json` summaries; synthetic corpus only).

### Decisions

- **One `results.json` per spike.** Each CLI command merges its measurement into one candidate's entry, so the UAT run can be done step by step and resumed.
- **Quality numbers come from the eval runner** (`--eval-results`), keeping only `overall` and `categories`. Per-case transcripts stay in the git-ignored `evals/reports/`.
- **Tool-call scoring:** a schema violation makes a call invalid even if the tool is right. "Right arguments" uses matchers that tolerate formatting (e.g. `1,250` = `1250.0`, case-insensitive strings). Only the first call is scored.
- **Thresholds:** NFR-001/002 are read from the "10 chats + 2 summaries" measurement, which is the condition the PRD states. Chat-only levels (1/5/10) are reported alongside.
- **Probe rules:**
  - cache_salt: the vLLM prefix-cache hit counter must rise for the same salt and stay flat for another salt.
  - priority: a high-priority request saturated behind 24 low-priority streams (more than `max_num_seqs`) must start in under half the median TTFT of the queued low-priority ones.
- **gpt-oss-20b** uses vLLM's `openai` tool parser, not hermes (noted in the README). Whether it starts on Ampere is itself a result.
- **Test config:** `evals/spike/pytest.ini` turns on `asyncio_mode = auto`, because a run from the repo root doesn't pick up the backend's pytest settings.
