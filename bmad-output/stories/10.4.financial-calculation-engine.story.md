# 10.4: Financial calculation engine

**Story ID:** 10.4
**Epic:** 10 — Excel Processing
**Slug:** financial-calculation-engine
**Status:** ready-for-dev

## Story

As a **banker**,
I want **growth, CAGR, margins, ratios and multiples computed exactly from cited inputs, with the formula shown**,
so that **no figure in an answer is the model's arithmetic**.

## Acceptance Criteria

1. **Metrics:** `calculate(metric, inputs) -> CalcResult` supports:
   - `growth` ((b − a) / |a|, %);
   - `cagr` ((end / start)^(1/years) − 1, %);
   - `margin` (part / whole, %);
   - `ratio`, `multiple` (e.g. EV / EBITDA, x);
   - `sum`, `mean`.

   All arithmetic uses `Decimal` with a fixed context (precision 34). No floats anywhere.
2. **Inputs:** each `CalcInput` has:
   - `value: Decimal` and `unit` (a `guardrails.grounding.Unit`; currencies must agree);
   - an optional `scale`, `period` label and `ref` (`document_id` + locator, e.g. `p.12` or `Sheet1!C4`).

   Every input is echoed in the result with its ref.
3. **Result:**
   - `value`, `unit` (PCT for growth/CAGR/margin, MULTIPLE for multiples, the input unit for sum and mean);
   - a display value rounded **half-up to 2 decimals**;
   - a plain-English formula with the inputs substituted, e.g. `CAGR = (1,250.0 / 812.4)^(1/3) − 1 = 15.45%`;
   - `as_grounding_value()`, which returns an `ExplicitValue` so 4.5/9.10 can ground it.
4. **Errors:** `CalcError(code)`, with codes:
   - `zero_denominator`, `negative_base` (CAGR with start ≤ 0 or a sign change);
   - `mismatched_units` (currencies, or PCT mixed with money), `mismatched_periods` (when period labels are given and inconsistent);
   - `too_few_inputs`, `invalid_years` (≤ 0).

   Messages are user-facing and contain no other data.
5. **Correctness:** 100% of ≥ 60 reference cases match hand-computed references to 2 dp, including edge values (very large crore amounts, tiny percentages, negative growth). A property test checks `growth(a, a·(1+g))` = g within 1e-20.

## Dev Notes

- **Calculations:** growth %, CAGR, margins, ratios, multiples, sums and averages, computed by the calculation engine and never estimated by the model. Results match a reference to 2 dp; the answer states the formula and inputs with citations; invalid inputs produce clear messages. [Source: prd.md#FR-023]
- **Engine contract:** `calculate` uses `Decimal` with explicit input references. [Source: architecture.md#ADR-030]
- **Tool `calculate(metric, inputs)`:** a Decimal engine with input references (wrapped as a tool in 10.5). [Source: architecture.md#ADR-026]
- **Grounding:** calculation outputs are part of the grounding set. Use `ExplicitValue` from 4.4. [Source: architecture.md#ADR-025]
- **CAGR with fractional exponents:** `Decimal` has no general power. Use `exp(ln(x)/n)` via `Decimal.ln()` / `Decimal.exp()` in the fixed context, then quantise. Document the precision. [Inference]
- Pure module: no FastAPI, no I/O (import-linter). [Source: architecture.md#ADR-038]

## Testing

- **Approach:** table-driven reference cases + property tests.
- **Per-AC verification:**
  - AC #1 → each metric's cases.
  - AC #2 → refs are echoed; mixed currencies are rejected.
  - AC #3 → formula text and display rounding (2.345 → 2.35, half-up); `as_grounding_value` round-trips through `grounding.match`.
  - AC #4 → every error code.
  - AC #5 → ≥ 60 cases + the property test.
- **Edge cases:** a year count given as a fraction (2.5 years); values in lakh vs crore normalised by `scale`; a mean over 1 input; sum of negatives.
