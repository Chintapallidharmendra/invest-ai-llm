# 2.1: Users, sessions schema and passwords

**Story ID:** 2.1
**Epic:** 2 — Authentication, Roles & Administration
**Slug:** users-sessions-schema-and-passwords
**Status:** ready-for-dev

## Story

As the **builder**,
I want **the identity tables, repositories and password handling in place**,
so that **login, admin user management and roles (2.2–2.4) build on a secure, tested base**.

## Acceptance Criteria

1. Migration `2_1_auth_tables` creates:
   - **`users`**: `username` citext unique, `email` citext unique, `role` enum `user|admin|compliance`, `status` enum `invited|active|locked|deactivated`, `password_hash` null, `failed_login_count` int, `locked_until` null, `last_login_at` null, timestamps
   - **`sessions`**: `user_id` FK, `token_hash` bytea unique, `created_at`, `last_seen_at`, `expires_at`, `revoked_at` null, `ip` inet null, `user_agent` text null; partial index on `(user_id) WHERE revoked_at IS NULL`
   - **`password_tokens`**: `user_id` FK, `token_hash` bytea unique, `purpose` enum `invite|reset`, `expires_at`, `used_at` null, `created_by` FK users null
2. `auth.repository` provides async typed persistence methods only: create/get users by id, username or email; update status, role and counters; create, get-by-hash, touch and revoke sessions, revoke all sessions for a user; create, get-valid-by-hash and mark-used tokens, invalidate all tokens for a user.
3. `auth.passwords` hashes and verifies with **Argon2id** via `pwdlib` (library defaults or stronger), supports `needs_rehash`, and provides `verify_dummy()` to equalise timing for unknown users.
4. `auth.policy.validate(password, username) -> list[ReasonCode]` enforces:
   - ≥ 12 characters
   - not in the **bundled top-100k breached-password list** (case-insensitive, loaded once into memory)
   - does not contain the username

   It applies no composition rules.
5. `auth.tokens` provides `generate_token()` (32 random bytes, URL-safe) and `hash_token()` (SHA-256 bytes). Raw tokens are never persisted or logged.

## Dev Notes

- **Passwords:** Argon2id via `pwdlib[argon2]`; policy ≥ 12 characters, rejected if in a
  bundled top-100k breached list (no external lookup), no composition rules. **Sessions**
  store `sha256(token)` with created, last-seen, expiry (12 h absolute), revoked, ip and
  user-agent. **Set-password tokens** store `sha256(token)`, purpose, 24 h expiry and
  used-at. Raw tokens are never persisted or logged. [Source: architecture.md#ADR-006]
- **Roles:** `user`, `admin`, `compliance`; admin has no content access (enforced in later
  stories via RLS). [Source: architecture.md#ADR-023] [Source: prd.md#FR-005]
- Identity tables hold no deal content, so **no RLS** and no field encryption.
  [Inference, consistent with ADR-023/ADR-028 scope: content tables only]
- Naming: plural snake_case tables, citext for case-insensitive unique fields, UUIDv7 PK
  default `uuidv7()`. [Source: architecture.md#ADR-004] [Source: architecture.md#ADR-005]
- One migration file per story, named `2_1_...`. [Source: epics.md#shared-file-conventions-parallel-safety-rules-for-every-story]
- Breached-password list: use a permissively licensed common-password list (e.g. SecLists,
  MIT) and record its source and licence in `auth/data/README.md`. It ships offline.
  [Inference] [Source: architecture.md#ADR-034]

## Testing

- **Approach:** unit tests (passwords, policy, tokens) + integration tests (repository, migration) with the `pg` fixture.
- **Per-AC verification:**
  - AC #1 → upgrade/downgrade; a duplicate username differing only by case is rejected.
  - AC #2 → each repository method round-trips; revoke-all affects only the target user.
  - AC #3 → hash/verify; a wrong password fails; `needs_rehash` is true for weaker params; `verify_dummy` takes comparable time (within 30%).
  - AC #4 → "password1234" (in the list) rejected; 11 characters rejected; a password containing the username rejected; a strong passphrase accepted.
  - AC #5 → token length and entropy; the hash is deterministic.
- **Fixtures:** small test breached list override via settings.
- **Edge cases:** Unicode passwords (NFKC normalise before checks); an empty username; list file missing (fail at startup with a clear error).
