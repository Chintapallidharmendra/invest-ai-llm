# 2.1: Users, sessions schema and passwords

**Story ID:** 2.1
**Epic:** 2 — Authentication, Roles & Administration
**Slug:** users-sessions-schema-and-passwords
**Status:** ready-for-dev

## Story

As the **builder**,
I want **the identity tables, repositories and password handling in place**,
so that **login, admin user management and roles (2.2–2.4) build on a secure, tested base**.

## Acceptance Criteria

1. Migration `2_1_auth_tables` creates:
   - **`users`**: `username` citext unique, `email` citext unique, `role` enum `user|admin|compliance`, `status` enum `invited|active|locked|deactivated`, `password_hash` null, `failed_login_count` int, `locked_until` null, `last_login_at` null, timestamps
   - **`sessions`**: `user_id` FK, `token_hash` bytea unique, `created_at`, `last_seen_at`, `expires_at`, `revoked_at` null, `ip` inet null, `user_agent` text null; partial index on `(user_id) WHERE revoked_at IS NULL`
   - **`password_tokens`**: `user_id` FK, `token_hash` bytea unique, `purpose` enum `invite|reset`, `expires_at`, `used_at` null, `created_by` FK users null
2. `auth.repository` provides async typed persistence methods only: create/get users by id, username or email; update status, role and counters; create, get-by-hash, touch and revoke sessions, revoke all sessions for a user; create, get-valid-by-hash and mark-used tokens, invalidate all tokens for a user.
3. `auth.passwords` hashes and verifies with **Argon2id** via `pwdlib` (library defaults or stronger), supports `needs_rehash`, and provides `verify_dummy()` to equalise timing for unknown users.
4. `auth.policy.validate(password, username) -> list[ReasonCode]` enforces:
   - ≥ 12 characters
   - not in the **bundled top-100k breached-password list** (case-insensitive, loaded once into memory)
   - does not contain the username

   It applies no composition rules.
5. `auth.tokens` provides `generate_token()` (32 random bytes, URL-safe) and `hash_token()` (SHA-256 bytes). Raw tokens are never persisted or logged.

## Dev Notes

- **Passwords:** Argon2id via `pwdlib[argon2]`; policy ≥ 12 characters, rejected if in a
  bundled top-100k breached list (no external lookup), no composition rules. **Sessions**
  store `sha256(token)` with created, last-seen, expiry (12 h absolute), revoked, ip and
  user-agent. **Set-password tokens** store `sha256(token)`, purpose, 24 h expiry and
  used-at. Raw tokens are never persisted or logged. [Source: architecture.md#ADR-006]
- **Roles:** `user`, `admin`, `compliance`; admin has no content access (enforced in later
  stories via RLS). [Source: architecture.md#ADR-023] [Source: prd.md#FR-005]
- Identity tables hold no deal content, so **no RLS** and no field encryption.
  [Inference, consistent with ADR-023/ADR-028 scope: content tables only]
- Naming: plural snake_case tables, citext for case-insensitive unique fields, UUIDv7 PK
  default `uuidv7()`. [Source: architecture.md#ADR-004] [Source: architecture.md#ADR-005]
- One migration file per story, named `2_1_...`. [Source: epics.md#shared-file-conventions-parallel-safety-rules-for-every-story]
- Breached-password list: use a permissively licensed common-password list (e.g. SecLists,
  MIT) and record its source and licence in `auth/data/README.md`. It ships offline.
  [Inference] [Source: architecture.md#ADR-034]

## Testing

- **Approach:** unit tests (passwords, policy, tokens) + integration tests (repository, migration) with the `pg` fixture.
- **Per-AC verification:**
  - AC #1 → upgrade/downgrade; a duplicate username differing only by case is rejected.
  - AC #2 → each repository method round-trips; revoke-all affects only the target user.
  - AC #3 → hash/verify; a wrong password fails; `needs_rehash` is true for weaker params; `verify_dummy` takes comparable time (within 30%).
  - AC #4 → "password1234" (in the list) rejected; 11 characters rejected; a password containing the username rejected; a strong passphrase accepted.
  - AC #5 → token length and entropy; the hash is deterministic.
- **Fixtures:** small test breached list override via settings.
- **Edge cases:** Unicode passwords (NFKC normalise before checks); an empty username; list file missing (fail at startup with a clear error).

  - AC #1:
    - Upgrade and downgrade to `1_11_jobs` drop and recreate all three tables and the three enums.
    - Column types are checked (`citext`, `bytea`, `inet`, enums), as is the partial index `(user_id) WHERE revoked_at IS NULL`. RLS is off.
    - `ASHA` vs `Asha` and `ASHA@Example.TEST` vs `asha@example.test` are rejected as duplicates.
    - Check constraints reject: an empty or >64-char username, an `active` user without a password, and a token hash ≠ 32 bytes.
    - Deleting a user cascades to sessions and tokens, and sets `created_by` to NULL.
  - AC #2:
    - Every repository function round-trips.
    - `revoke_all_sessions` (with and without `except_session_id`) touches only the target user; so does `invalidate_password_tokens` (all or by purpose).
    - Tokens are single-use: the second `mark_password_token_used` returns False, and expiry is exclusive at `expires_at`.
    - A failed duplicate insert leaves the caller's transaction usable.
    - The raw token appears in no `sessions` / `password_tokens` row.
  - AC #3:
    - Hashes are `$argon2id$v=19$m=65536,t=3,p=4$…` (pwdlib defaults) and salted. A wrong password fails, and an unknown hash format gives False.
    - `needs_rehash` is True for t=1/m=8 MiB and for a bcrypt hash; `verify_and_rehash` upgrades such hashes.
    - NFKC: decomposed é, the ﬁ ligature and ½ all verify.
    - `verify_dummy` times within 30% of a real verify (interleaved medians, warmed).
  - AC #4:
    - `password1234` / `PASSWORD1234` → `breached`; 11 characters → `too_short`; `asharao-picks-mangoes` for user `AshaRao` → `contains_username`.
    - A strong passphrase passes. `zzzzqqqqvvvv` passes (no composition rules).
    - An empty or blank username skips the username rule; fullwidth `ＡＳＨＡ` matches `asha`.
    - Length counts code points after NFKC.
    - The small-list override works through `AuthSettings`.
    - A missing, empty or non-UTF-8 list raises `BreachedListError` with the path.
    - The bundled list is loaded once (same object on repeated calls).
  - AC #5: `generate_token()` gives 43 URL-safe chars that decode to 32 bytes. 2,000 tokens are unique, with > 7.9 bits/byte entropy. `hash_token` is deterministic SHA-256 (32 bytes).
- **Decisions / deviations:**
  - **Breached list:** SecLists `xato-net-10-million-passwords-100000.txt` (Mark Burnett's 10M dataset; SecLists is MIT). It is bundled verbatim (SHA-256 `1472aafa…388b`, 100,000 lines, 96,517 unique once case-folded). Source, licence and hash are in `auth/data/README.md`. A gitleaks scan of the file (Docker `zricethezav/gitleaks`, repo config) found no leaks, so no allowlist entry was needed.
  - **Normalisation:** NFKC is applied to passwords before hashing, verifying and policy checks, so hashing and policy agree on what "the password" is. The policy compares case-insensitively with `casefold()`, and the username check uses NFKC + casefold + strip.
  - **Extra policy rule:** `too_long` above `password_max_length` (default 1024; NIST allows ≥ 64), so Argon2 can't be fed huge inputs. There are no composition rules.
  - **Repository shape:**
    - Module functions take the caller's `AsyncSession`, so services (2.2–2.4) compose several steps in one `transaction()`. It holds no policy (lockout threshold, idle timeout).
    - Times default to `utcnow()` and take `now=` for tests.
    - Beyond the AC list: `set_password_hash`, `increment_failed_logins` (returns the new count), `set_locked_until`, `record_successful_login` (resets the counter and lock, stamps `last_login_at`), and `UserSession.is_active(now)` (revoked / absolute expiry).
    - `create_user` raises `DuplicateUserError(field)` from a savepoint.
    - `invalidate_password_tokens` expires tokens (`expires_at = now`) rather than setting `used_at`, so `used_at` always means "redeemed".
    - `get_session_by_hash` returns revoked and expired rows too; callers check `is_active` and the idle timeout.
  - **Schema additions:** `password_tokens.created_at`, and check constraints (username 1–64 chars, email 3–254, `failed_login_count ≥ 0`, a password unless `invited`, 32-byte token hashes, session `expires_at > created_at`). Session and token FKs `ON DELETE CASCADE`; `created_by` `ON DELETE SET NULL`. `email` is NOT NULL (FR-001: the admin enters username, email, role). `sessions.ip` maps to `ipaddress` objects (asyncpg); `create_session` accepts a string and validates it.
  - **Settings** (`APP_AUTH_*`): `password_min_length` (12), `password_max_length` (1024), `breached_passwords_path`. Also the ADR-006 lifetimes, so 2.2/2.3 don't need to edit this file: session absolute TTL 12 h, idle timeout 60 min, touch interval 60 s, set-password token TTL 24 h.
  - The dummy hash for `verify_dummy` is computed once, lazily, from a fixed non-secret input.
