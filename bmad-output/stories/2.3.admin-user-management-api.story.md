# 2.3: Admin user management API

**Story ID:** 2.3
**Epic:** 2 — Authentication, Roles & Administration
**Slug:** admin-user-management-api
**Status:** ready-for-dev

## Story

As an **admin**,
I want **to create users with a role, hand them a one-time set-password link, and deactivate or unlock them**,
so that **accounts are provisioned without email, and access ends the moment someone leaves**.

## Acceptance Criteria

1. **Create:** `POST /api/v1/admin/users` `{username, email, role}` (admin only):
   - creates the user as `invited`;
   - emits the core event `auth.user_created(user_id, session)` inside the transaction, so 8.2 creates the private space and its key atomically;
   - returns the user plus a **show-once** link `https://<site>/set-password#t=<token>` (24 h, purpose `invite`).
   - A duplicate username or email → `409 user_exists` (field named).
2. **Links:**
   - `POST /api/v1/admin/users/{id}/set-password-links` re-issues a link (purpose `reset`, or `invite` while still invited). Earlier links are expired, the response returns the new link once, and it is audited.
   - The raw token is never stored, logged or audited.
3. **Redeem:** `POST /api/v1/auth/set-password` `{token, username, new_password}` (in `app/auth/routes_links.py`):
   - the token must be valid, unused and for that username;
   - the password policy (2.1) is applied, with reason codes in a `422 password_rejected`;
   - in one transaction it marks the token used (checking the return value), invalidates the user's other tokens, sets the hash, activates the user and **revokes all sessions**.
   - Any failure gives a generic `400 link_invalid`.
4. **Manage:**
   - `GET /api/v1/admin/users` lists `id`, `username`, `email`, `role`, `status`, `last_login_at`, `created_at`, with no content of any kind.
   - `PATCH /api/v1/admin/users/{id}` changes `role` or `status` (`deactivated`/`active`) or unlocks.
     - Deactivation revokes all sessions in the same transaction, so the next request gets 401 (≤ 5 s).
     - Its response includes metadata counts so the UI can prompt about the user's spaces (FR-003).
   - `POST /api/v1/admin/users/{id}/session-revocations` revokes all sessions.
   - Guards: an admin cannot remove the last admin or their own admin role (`409`).
5. **Roles and audit:**
   - Every admin route uses `require_role("admin")`, so non-admins get 403 and an audit row.
   - Role changes take effect on the next request.
   - Audit events: `admin.user_created`, `admin.link_issued`, `admin.user_updated` (`changed: enum set`), `admin.sessions_revoked` (`app/admin/audit_events.py`); `auth.link_redeemed` (`app/auth/audit_events_links.py`).
6. **Bootstrap:** `python -m app.admin.bootstrap --username U --email E` creates the **first admin** (only when no admin exists) and prints the one-time link to stdout. Nothing is logged.

## Dev Notes

- **Account creation (FR-001):**
  - The admin creates a user and gets a one-time set-password link to share manually. The link is shown once, expires in 24 h, is single-use and requires the username.
  - Re-issuing invalidates earlier links, and using a link ends all of the user's sessions.
  - Duplicates are rejected; non-admins are refused and audited.

  [Source: prd.md#FR-001]
- Deactivation ends sessions within 5 s; status and last sign-in are visible; the admin is told to transfer or confirm deletion of spaces. [Source: prd.md#FR-003]
- No admin endpoint returns content, titles or file names; last-admin and self-demote guards; role changes audited. [Source: prd.md#FR-005]
- The raw link `https://<host>/set-password#t=<token>` sits in the URL fragment, so it doesn't reach server logs or Referer headers. Redeeming requires token + username + new password, and success marks the token used, invalidates other tokens, revokes all sessions and activates the user. [Source: architecture.md#ADR-006]
- **REST:** `POST /admin/users/{id}/set-password-links`, `POST /admin/users/{id}/session-revocations`. [Source: architecture.md#6-api-specifications] [Source: architecture.md#ADR-004]
- The site base URL for links comes from an admin setting (`APP_ADMIN_SITE_URL`). Q11 (the approved channel for sharing links) is organisational. [Source: addendum.md#open-questions]

## Testing

- **Approach:** API tests with `app_client`, `pg`, a logged-in admin fixture (via 2.2), and 8.2's subscriber active.
- **Per-AC verification:**
  - AC #1 → user is invited and a private space + space key exist; a rollback (forced error) leaves no user and no space; duplicates → 409.
  - AC #2 → after a re-issue, the old link fails; the token never appears in captured logs or audit rows.
  - AC #3 → happy path activates and revokes sessions; wrong username, expired, reused or concurrent double-redeem fail with the same 400; a policy rejection → 422 with reasons.
  - AC #4 → deactivated user's next request → 401; last-admin and self-demote → 409; the list holds no content fields.
  - AC #5 → a user-role call to admin routes → 403 + audit; `assert_no_content` on all events.
  - AC #6 → bootstrap twice: the second run refuses; the link works.
- **Edge cases:** case-variant duplicate usernames (citext); deactivating an invited user; unlocking a locked user resets the counter.
