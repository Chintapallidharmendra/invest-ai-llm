# 2.4: Change own password

**Story ID:** 2.4
**Epic:** 2 — Authentication, Roles & Administration
**Slug:** change-own-password
**Status:** ready-for-dev

## Story

As a **user**,
I want **to change my password while signed in**,
so that **I can rotate it myself, and any other device using my account is signed out**.

## Acceptance Criteria

1. `POST /api/v1/auth/change-password` `{current_password, new_password}` (authenticated, CSRF-protected) verifies the current password.
   - A wrong current password → `400 current_password_invalid`, and it **counts toward the lockout** (5 → 15 min) like a failed login.
2. The new password goes through the 2.1 policy (length, breached list, username) → `422 password_rejected` with reason codes. Reusing the current password → `422 password_unchanged`.
3. In one transaction it:
   - sets the new Argon2id hash;
   - **revokes every other session** of the user, keeping the current one;
   - records `auth.password_changed` with a revoked-session count.

   Returns `204`.
4. No password value appears in logs, audit rows or error bodies. Responses don't reveal which policy check failed beyond the reason codes.

## Dev Notes

- **FR-038:** requires the current password; policy ≥ 12 chars and not breached; a change ends the user's other sessions and is audited. [Source: prd.md#FR-038]
- Password change requires the current password and revokes all other sessions. [Source: architecture.md#ADR-006]
- **Policy:** NIST-style: length + breached list, no composition rules. [Source: architecture.md#ADR-006]
- The route lives in `app/auth/routes_password.py`, mounted by 2.2's `routes_*` discovery, so it doesn't collide with 2.3's `routes_links.py`. [Inference]

## Testing

- **Approach:** API tests with two logged-in sessions for one user.
- **Per-AC verification:**
  - AC #1 → wrong current password ×5 → locked.
  - AC #2 → every reason code; same password → 422.
  - AC #3 → the other session gets 401, the current one still works; audit count = 1.
  - AC #4 → a planted password is absent from logs and responses.
- **Edge cases:** an NFKC-equivalent new password counts as "unchanged"; concurrent change requests.
