# 2.5: Auth pages UI

**Story ID:** 2.5
**Epic:** 2 — Authentication, Roles & Administration
**Slug:** auth-pages-ui
**Status:** ready-for-dev

## Story

As a **user**,
I want **sign-in, set-password and change-password pages**,
so that **I can get into the app from my link and manage my password without help**.

## Acceptance Criteria

1. **`/login`:**
   - Username + password form; one generic error for any failure, and the 429 message for rate limits.
   - On success it goes to `next` (same-origin paths only) or the home page.
   - Shows "Forgot password? Contact your administrator." (FR-004).
   - Never stores credentials or tokens in local/session storage.
2. **`/set-password`:**
   - Reads the token from the URL **fragment** (`#t=`) and immediately removes it from history (`history.replaceState`).
   - Asks for username, new password and confirmation; shows the policy (≥ 12 characters, not a common password).
   - Maps `422` reason codes to plain messages; a `400 link_invalid` shows "This link is invalid or expired. Ask your administrator for a new one."
   - Success → `/login`.
3. **`/account/password`** (authenticated): current + new + confirm. A success notice says other devices were signed out.
4. **Auth state:**
   - An `AuthProvider` runs the `/auth/me` query and supplies `AuthContext` (`anonymous` on 401), replacing the `unknown` default from 1.10.
   - `RequireAuth` redirects anonymous users to `/login?next=…`.
   - The layout shows the username and a **Sign out** action (`POST /auth/logout`, then clear the query cache and go to `/login`).
5. **Quality:**
   - Request and response types are generated (`make typegen`); none hand-written.
   - All pages pass axe with no violations and work by keyboard only.
   - Unit tests (Vitest + Testing Library) and a Playwright flow against the dev API: invite link → set password → login → change password → logout.

## Dev Notes

- **Frontend stack:** TanStack Query for server state; current user and CSRF from a `/auth/me` query + React context; no other state libraries; no hand-written API types. [Source: architecture.md#ADR-008]
- No auth state in localStorage. The link token sits in the URL fragment (never sent to the server in the URL). [Source: architecture.md#ADR-006]
- The sign-in page shows "Forgot password? Contact your administrator." [Source: prd.md#FR-004]
- Generic message for invalid credentials. [Source: prd.md#FR-002]
- **Client conventions (1.10):** the client adds `X-CSRF-Token` from `__Host-csrf`; `redirectOn401: false` for the login form; route modules are auto-discovered via `import.meta.glob`; `RequireAuth` / `AuthContext` already exist. [Source: frontend/src/api/client.ts] [Source: frontend/src/auth/RequireAuth.tsx]
- Only same-origin relative `next` targets are allowed (open-redirect protection). [Inference]

## Testing

- **Approach:** Vitest component tests with mocked fetch; Playwright e2e with the backend (fake LLM not needed); axe on every page.
- **Per-AC verification:**
  - AC #1 → generic error, 429 copy, `next` sanitising (`//evil.com`, `https://…` rejected).
  - AC #2 → fragment read then removed (`location.hash` empty); reason code mapping; invalid-link copy.
  - AC #3 → success notice.
  - AC #4 → anonymous redirect with `next`; sign-out clears the cache.
  - AC #5 → `tsc` strict passes; axe 0 violations; keyboard-only flow.
- **Edge cases:** the token present in the query string instead of the fragment (ignored); a slow `/auth/me` (loading state, no flash of protected content).
