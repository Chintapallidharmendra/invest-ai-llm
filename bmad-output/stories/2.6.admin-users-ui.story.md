# 2.6: Admin users UI

**Story ID:** 2.6
**Epic:** 2 — Authentication, Roles & Administration
**Slug:** admin-users-ui
**Status:** ready-for-dev

## Story

As an **admin (IT)**,
I want **a screen to list users, create them with a one-time set-password link, and change their status**,
so that **I can onboard and offboard bankers without the command line, and without ever seeing their content**.

## Acceptance Criteria

1. **Route `/admin/users`** (role `admin` only, nav entry "Users"). Other roles get the 404 page, never "forbidden". It lists users from `GET /api/v1/admin/users`: username, email, role, status, locked badge, last sign-in (IST, `DD-MMM-YYYY HH:mm`), created date.
2. **Create user:** a dialog takes username, email and role (`user` | `admin` | `compliance`) and posts `POST /admin/users`.
   - On 201 a **show-once panel** displays the link URL with a copy button, its expiry, and the text "This link is shown once. Share it through the approved internal channel."
   - Closing the panel discards the link from memory (it is not cached in TanStack Query, `localStorage` or the URL).
   - 409 (duplicate username or email) and 422 (validation) show the problem's `detail` next to the right field.
3. **Row actions** (dropdown):
   - **Re-issue link** → `POST /admin/users/{id}/set-password-links` → the same show-once panel.
   - **Deactivate / Reactivate** → `PATCH {status}`. Deactivation needs a confirm dialog that shows the `spaces` counts from the response of a dry read (see Dev Notes) and the FR-003 note that spaces are not deleted automatically.
   - **Unlock** (only when `locked`) → `PATCH {unlock: true}`.
   - **Change role** → `PATCH {role}` with a confirm dialog.
   - **Revoke sessions** → `POST /admin/users/{id}/session-revocations`, then a toast "N sessions ended".
4. **Errors:** every mutation shows problem `detail` in a toast; the "last admin" / "own admin role" refusals (FR-005) show their message and leave the row unchanged. All mutations invalidate the admin-users query scope.
5. **No content:** the screen shows only the fields above. Nothing on it requests any content endpoint (spaces, documents, conversations, outputs).

## Dev Notes

- **Endpoints (done in 2.3):** `GET/POST /admin/users`, `PATCH /admin/users/{id}` (`{role?, status?, unlock?}`, at least one), `POST /admin/users/{id}/set-password-links`, `POST /admin/users/{id}/session-revocations` (`{revoked}`). [Source: architecture.md#admin-admin-role-no-content]
- **Response shapes:** `AdminUser {id, username, email, role, status, locked, last_login_at, created_at}`; `CreatedUser {user, link: {url, purpose, expires_at}}`; `UpdatedUser {user, spaces: {private_spaces, owned_workspaces, sole_owner_workspaces, member_workspaces}}`. [Source: backend/app/admin/schemas.py, story 2.3 record]
- **Deactivation prompt:** the space counts come back on the `PATCH` response, not before it. Show the confirm dialog first (generic FR-003 text), then after success show a second notice with the counts, highlighting `sole_owner_workspaces > 0` ("transfer or close these workspaces"). [Inference, from story 2.3 follow-up "PATCH responses carry spaces counts"]
- **FR-001:** the link is shown once, expires in 24 h, is single-use. Re-issuing invalidates earlier links. [Source: prd.md#fr-001-admin-creates-a-user-account--must]
- **FR-003:** status and last sign-in visible; deactivating doesn't delete spaces; the admin is told to transfer or confirm deletion. [Source: prd.md#fr-003-admin-deactivates-users-and-revokes-sessions--must]
- **FR-005:** admin screens never show content, titles or file names; last-admin and own-role guards are server-side. [Source: prd.md#fr-005-three-roles-with-distinct-permissions--must]
- **Frontend conventions:** TanStack Query for server state, no global store; one problem parser (`api/problem.ts`); keys via `keyScope("adminUsers")` in `src/features/admin-users/queryKeys.ts`; routes auto-discovered from `src/routes/<name>/route.tsx` with `roles: ["admin"]` and `nav: {label: "Users"}`. [Source: architecture.md#adr-008-frontend-state-tanstack-query-for-server-state-no-global-store] [Source: frontend/src/routes/index.ts]
- **Types:** use `frontend/src/api/schema.d.ts` (run `make typegen`); never hand-write request types. [Source: architecture.md#adr-002-restjson-under-apiv1--sse-for-chat-streaming]
- **Dates:** ISO UTC from the API; display IST via `lib/format.ts`. [Source: architecture.md#adr-003-response-error-and-sse-event-conventions]

## Testing

- **Approach:** Vitest + Testing Library with mocked `fetch` (the `__tests__/fixtures.ts` helpers).
- **Per-AC verification:**
  - AC #1 → role `user` and `compliance` get the 404 page; admin sees rows, badges and IST dates.
  - AC #2 → after create, the URL is shown and copyable; after closing, it is absent from the DOM and from the query cache (`queryClient.getQueryCache().findAll()` holds no `url`); 409 maps to the field.
  - AC #3 → each action calls the right method, path and body; unlock appears only when locked.
  - AC #4 → a 409 "last admin" problem shows a toast and leaves the role unchanged; the list is refetched after each mutation.
  - AC #5 → the mocked fetch records only `/auth/me` and `/admin/*` paths.
- **Edge cases:** empty list; very long emails; a link panel closed by Escape.
