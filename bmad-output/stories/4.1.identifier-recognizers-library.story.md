# 4.1: High-risk identifier recognizers library

**Story ID:** 4.1
**Epic:** 4 — Guardrails & Data Protection
**Slug:** identifier-recognizers-library
**Status:** ready-for-dev

## Story

As **compliance**,
I want **one deterministic library that detects and masks high-risk personal identifiers**,
so that **chat blocking (4.2) and document masking (9.5) use the same, tested rules**.

## Acceptance Criteria

1. `guardrails.identifiers.detect(text) -> list[Finding]` finds these types, using Presidio built-ins `IN_PAN`, `IN_AADHAAR`, `IN_PASSPORT`, `IN_VOTER`, `CREDIT_CARD` plus custom recognizers:
   - `PAN`
   - `AADHAAR`, including partially masked forms like `XXXX XXXX 1234`
   - `BANK_ACCOUNT` (9–18 digits within 40 characters of context words)
   - `DEMAT_ID` (NSDL `IN` + 14 digits; CDSL 16 digits with context)
   - `CARD` (13–19 digits, Luhn-valid)
   - `UPI_ID` (`handle@psp` from a configurable PSP-suffix list)
   - `PASSPORT`, `VOTER_ID`

   `Finding` has `type`, `start`, `end`, `score`. **It never holds the matched value.**
2. `mask(text) -> MaskResult(text, findings)` replaces each finding with `[TYPE]`, merging overlaps. `detect_batch` / `mask_batch` handle many segments efficiently, for document ingestion.
3. **Benign allow-list** (never flagged): CIN, LLPIN, company GSTIN (including the PAN-like substring at positions 3–12), ISIN (`INE…`), NSE symbols, dates, monetary amounts, percentages, business emails and phone numbers.
4. Performance: `detect` on a 2,000-character message runs in **≤ 20 ms p95** on the UAT host (after warm-up); `mask_batch` processes ≥ 500 segments per second of ~1,000 chars.
5. Runs fully offline: the spaCy model loads from a configured local path (`APP_GUARDRAILS_SPACY_MODEL_PATH`), and the engine fails fast if it's missing. **Nothing logs matched values.**

## Tasks / Subtasks

- [ ] `identifiers/types.py`: `IdentifierType` enum, `Finding`, `MaskResult` (AC: #1, #2)

## Dev Notes

- **High-risk identifiers:** PAN, Aadhaar incl. partial, bank account with context,
  demat/DP ID, card (Luhn), UPI, passport, voter ID. These are **blocked in chat and masked
  in documents**. Business content (names, financials, contacts) is **not** flagged.
  [Source: prd.md#FR-012]
- **Pattern detail for authors:** PAN = 5 letters + 4 digits + 1 letter, any case,
  optional spaces. Aadhaar is 12 digits (4-4-4 with space or hyphen, or contiguous),
  including masked forms. Card is 13–19 digits passing Luhn. NSDL demat is `IN` + 14
  digits; CDSL is 16 digits. Not flagged: CIN/LLPIN, company GSTIN, ISIN, deal values,
  business contacts. [Source: addendum.md#fr-012-high-risk-identifier-patterns-for-test-suite-authors]
- The chat gate uses **high-risk IDs only, with no PERSON/EMAIL/PHONE blocking**.
  [Source: architecture.md#ADR-024]
- At ingestion, matches are replaced with `[TYPE]` and only masked text proceeds;
  counts and locators go to the report. [Source: architecture.md#ADR-027]
- Targets: ≥ 99% recall, ≤ 5% chat false positives (suite in 4.7). [Source: prd.md#NFR-005]
- Presidio's `IN_AADHAAR` validates the Verhoeff checksum. Partially masked forms can't be
  checksummed, so add a separate pattern with context. A GSTIN embeds the PAN at
  characters 3–12, so the allow-list must suppress PAN findings inside a GSTIN span.
  [Inference]
- No values in logs or traces; the library must not log findings beyond counts. [Source: architecture.md#ADR-033]
- This module may not import FastAPI (import-linter). [Source: architecture.md#ADR-038]
- Runs offline; the spaCy model is bundled under `/models`. [Source: architecture.md#ADR-034]

## Testing

- **Approach:** table-driven unit tests (≥ 10 positive and ≥ 5 negative cases per type), plus a benchmark test marked `perf`.
- **Per-AC verification:**
  - AC #1 → each type in its formats (spaced, hyphenated, lowercase PAN, inside sentences, at a string start or end).
  - AC #2 → mask output and placeholders; overlapping findings merged; batch equals single.
  - AC #3 → GSTIN `27ABCDE1234F1Z5` produces **no** PAN finding; CIN, ISIN, `₹1,23,45,678`, `+91 22 6000 0000` (business, no context) are not flagged.
  - AC #4 → benchmark thresholds.
  - AC #5 → a missing model path raises at init; logs captured during tests contain no planted value.
- **Fixtures:** a small inline sample set (the full suite comes in 4.7 from the corpus, 1.7).
- **Edge cases:** identifiers next to punctuation; Unicode digits; a 12-digit amount without Aadhaar context (must not be Aadhaar if the checksum fails); a 16-digit card failing Luhn (must not flag).
