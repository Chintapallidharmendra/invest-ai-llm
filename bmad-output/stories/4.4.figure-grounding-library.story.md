# 4.4: Figure grounding library

**Story ID:** 4.4
**Epic:** 4 — Guardrails & Data Protection
**Slug:** figure-grounding-library
**Status:** ready-for-dev

## Story

As a **banker**,
I want **every number the assistant shows to be checked against the source figures**,
so that **I never act on a made-up or mis-scaled figure from a deal document**.

## Acceptance Criteria

1. `grounding.extract_figures(text) -> list[Figure]` returns `span`, `raw`, `value: Decimal` (canonical) and `unit` (`INR`, `USD`, `EUR`, `PCT`, `BPS`, `MULTIPLE` (x), `COUNT`, `DATE`, `PLAIN`). It handles:
   - currency symbols and codes (`₹`, `Rs`, `INR`, `$`, `USD`, `€`)
   - scale words (`lakh`, `lac`, `crore`, `cr`, `mn`, `million`, `bn`, `billion`, `k`, `thousand`)
   - Indian (`1,00,000`) and international (`100,000`) grouping
   - negatives (`-5`, `(5)`), ranges (`10–12%`)
   - dates (`06-Oct-2026`, `31 March 2025`, `FY26` as a period label)
2. `build_grounding_set(sources)` takes source texts, table cells (with optional unit metadata) and explicit values, and returns canonical values with their origins.
3. `match(figure, grounding_set) -> MatchResult` matches when canonical values are equal **within the figure's display precision** (e.g. `4,215 cr` matches source `4,215.37 cr`; `4,200 cr` does not).
   - Unit equivalence holds (`₹4,215 crore` == `₹42,150 million` == `42.15 bn`); PCT vs BPS converts.
   - Cross-currency never matches.
4. **Exemptions** (`is_exempt(figure, context)`): counts ≤ 12 written without a unit; list ordinals; period labels (`FY26`, `Q2 FY26`, `H1`, `1 year`, `3Y`, `2023–2026`); years used inside a period label; page, slide or section numbers inside citations.
5. The library is pure (no I/O) and deterministic, with ≥ 120 table-driven unit tests. A 1,000-token text is processed in ≤ 5 ms on the UAT host.

## Dev Notes

- **Grounding rule:** every number in an answer must appear in, or be computed by the
  calculation engine from, the selected documents and sheets. Unit and format variants
  match (₹ crore vs million; 1.2bn vs 1,200m). [Source: prd.md#FR-036]
- **Grounding set** = numbers in the turn's retrieved chunks and tables, sheet cells from
  tools, operation and calculation outputs, the user message and the current date.
  Normalisation: ₹/Rs, commas, lakh/crore/million/billion, %, bps, dates to ISO. Match
  within display precision. Exempt: small counts ≤ 12 without unit, list ordinals, period
  labels. [Source: architecture.md#ADR-025] [Source: architecture.md#ADR-011]
- **Consumers:**
  - the output gate holds back spans containing digits and calls this library (Story 4.5);
  - summary jobs ground every bullet against cited chunks (9.10);
  - comparisons build changed-figure tables (9.12).

  [Source: architecture.md#ADR-029]
- Documents keep their own convention (₹ crore or USD million). Both Indian and
  international grouping must parse. [Source: prd.md#response-scope--style-policy]
- Pure library: no FastAPI, no I/O (import-linter). [Source: architecture.md#ADR-038]
- Precision inference: "4,215 cr" has 0 decimals at crore scale, so it matches any source
  value in [4,214.5, 4,215.5) crore. [Inference]
- Ambiguity: "1.2" with no unit near a "%"-unit table cell should match as PCT only if
  the table metadata says so; otherwise use PLAIN. [Inference]

### Decisions

- **Canonical values:**
  - Money is in base units with scale applied (`₹4,215 cr` → 42,150,000,000).
  - PCT is in percent and BPS in basis points; they are compared in percent.
  - DATE is `YYYYMMDD`, with `00` for parts not written (`Figure.iso` gives the ISO form).
  - `Figure.step` is the display resolution, and matching uses [v − step/2, v + step/2).
  - `Figure.number` is the numeral as written; `range_span` ties the two ends of a range.
- **Signs:**
  - An explicit minus (`signed`) matches only negative values.
  - Unsigned figures match either sign, so "a loss of ₹120 cr" matches a source "(120)".
  - Accounting parentheses around a bare number make the value negative but not `signed`.
  - Parentheses around an amount with a currency or unit (`(US$ 505 mn)`) are read as an aside.
- **Currency is strict:** an amount with a currency matches only that currency. Unit-less figures may match a source's canonical amount (`42.15 bn` vs `₹4,215 crore`) or the numeral the source wrote (`4,215` vs `₹4,215 cr`). As a result, `₹4,215` against a "₹ crore" cell fails, which catches a mis-scaled figure.
- **Table cells:** unit/scale metadata applies only to bare numbers. A cell that states its own unit keeps it. Without metadata, `1.2` stays PLAIN, per the Dev Notes.
- **Dates:** a figure matches at its own precision: a year matches any date in that year or an FY label with that end year; a month matches any day in it. Numeric dates are read DD/MM unless that's impossible. Two-digit years mean 20YY. `2025-03` is a month; `2011-12` is FY 2011-12.
- **Exemptions beyond the AC wording:**
  - Locators (page/slide/section/§/clause/cell ranges/`[3]` footnotes) are exempt wherever they appear, not only inside citations.
  - Ordinals are exempt up to 12th.
  - Durations count as period labels only in years (`1 year`, `3Y`, `5-year`), not months.
  - A year is exempt after `fiscal`/`FY`/`calendar (year)`/`year`, or before `financial year`.
- **Never extracted as figures:** `cite:` targets, URLs, digits glued to letters, and version-like `3.2.1`. Times such as `10:30` are extracted as two plain numbers.
- **API beyond the ACs:**
  - `ground_text(text, set)` returns a `MatchResult` per figure, with reason EXEMPT, MATCHED, NOT_FOUND or CROSS_CURRENCY. The reasons are there for 4.5's audit metadata.
  - `GroundingSet` is immutable and indexed per dimension with bisect, and `|` combines two sets.
- **Speed work:** a shared "token start" look-behind wraps the grammar, so mid-word positions are rejected before any alternative is tried; this roughly halved the time. Citation-link spans are cached per text (`lru_cache(16)`), so the library stays deterministic.
