# 7.1: Audit writer and hash chain

**Story ID:** 7.1
**Epic:** 7 — Data Lifecycle, Audit & Compliance
**Slug:** audit-writer-and-chain
**Status:** ready-for-dev

## Story

As **compliance**,
I want **a tamper-evident, metadata-only audit trail that every module writes through one entry point**,
so that **we can show who did what and when, without the audit itself becoming a copy of confidential content**.

## Acceptance Criteria

1. Migration `7_1_audit` creates:
   - `audit_events`, **partitioned monthly** by `occurred_at`: `id`, `seq` bigint unique, `occurred_at`, `correlation_id`, `actor_user_id`, `event_type`, `target_type`, `target_id`, `priority` (`normal|high`), `payload` jsonb, `prev_hash` bytea, `hash` bytea; indexes `(actor_user_id, occurred_at)` and `(event_type, occurred_at)`
   - `audit_anchors(partition_name, last_seq, last_hash, dropped_at)`
   - a trigger rejecting UPDATE and DELETE on `audit_events`
   - grants: `app_rw` has **INSERT and SELECT only**
   - partitions for the current month plus the next two
2. **Event registry:** modules declare events in `app/<module>/audit_events.py` as subclasses of `AuditEvent` with a class-level `event_type` (`<domain>.<action>`). Field types are restricted to UUID, enums, int, bool, datetime, timedelta, `VersionStr` (allow-listed pattern) and `KeyedHash`. A **CI check** `python -m app.audit.check_models` fails if any registered model has an unconstrained `str` field (or any free-text type).
3. `audit.writer.record(event, *, actor_user_id, correlation_id, target_type=None, target_id=None, priority="normal")`:
   - serialises the payload to canonical JSON (sorted keys, no whitespace);
   - takes a transaction-scoped advisory lock;
   - assigns `seq = last + 1` and `prev_hash = last.hash`;
   - computes `hash = SHA-256(prev_hash || canonical_json(row without hash))`.

   `KeyedHash.of(value)` = HMAC-SHA256 with the audit key from `/run/secrets/audit_hmac_key`.
4. **Daily verification job** `audit_verify`, registered via `jobs.scheduler.register_cron`, recomputes the chain over new rows since the last verified `seq` (full recompute weekly). On mismatch it emits core event `audit.chain_mismatch` (consumed later by admin alerts) and records `audit.verify_failed`; success records `audit.verified`.
5. **Retention primitives:** a monthly job creates future partitions. `drop_partition_with_anchor(name)` writes the anchor (last seq and hash) **before** detaching and dropping. Retention months come from a setting (default 60). The scheduled drop job is registered but no-ops until data is older than retention.
6. A **canary test helper** `assert_no_content(payload)` (used by every module's tests) fails if any payload string value isn't an allow-listed enum, UUID, version or hash format.

## Dev Notes

- **Audit** is written only through `audit.writer.record`. Each row has `seq` (gap-free
  via a single-writer advisory lock), `prev_hash` and
  `hash = sha256(prev_hash || canonical_json(row without hash))`. The `app_rw` role has
  no UPDATE/DELETE, plus a trigger. Daily verification raises an admin alert on mismatch.
  Monthly partitions are dropped after retention, with chain anchors. [Source: architecture.md#ADR-016]
- **Metadata-only by type (v2):** fields restricted to UUIDs, enums, integers, booleans,
  timestamps, durations, allow-listed version strings and **keyed hashes (HMAC with an
  audit key)**. **No free-text `str` fields; a CI check rejects them.** No titles, file
  names, workspace names, prompts, answers or error messages. Compliance reads the audit
  (later story); admin cannot. Break-glass events carry `high` priority. [Source: architecture.md#ADR-032]
- PRD: 100% of listed events recorded, not alterable through the app; canary test shows
  0 content occurrences; 5-year default retention. [Source: prd.md#FR-031] [Source: prd.md#NFR-017] [Source: prd.md#NFR-023]
- **Per-module audit event files** avoid a contended central file. The registry
  auto-discovers `app/<module>/audit_events.py`. [Source: epics.md#shared-file-conventions-parallel-safety-rules-for-every-story]
- Cron registration uses the jobs scheduler from 1.11 (`register_cron`, timezone
  Asia/Kolkata). [Source: architecture.md#ADR-017]
- Secrets: audit HMAC key file `audit_hmac_key` under `/run/secrets`. [Source: architecture.md#ADR-021] (amendment)
- A keyed hash prevents guessing-based confirmation (e.g. hashing a suspected deal name to
  compare). Never use plain SHA-256 of content values in payloads. [Source: architecture.md#ADR-032]
- **Advisory lock** scope: `pg_advisory_xact_lock(<constant>)` serialises writers. At ~10
  users the throughput is ample. [Inference]

### Decisions

- **`record(..., session=None)`:**
  - The AC's signature plus an optional `session`, so the event commits or rolls back with the caller's transaction (the rollback edge case).
  - Without it, the event gets its own `transaction()`.
  - `correlation_id` accepts a UUID or its string; anything else raises.
- **`seq` uniqueness:** Postgres can't enforce a unique constraint across partitions without the partition key. The constraint is therefore `UNIQUE (seq, occurred_at)`. `seq` is gap-free and unique by construction (the advisory lock), and verification checks it (gap/out-of-order → `GAP`).
- **Hash material:** canonical JSON (sorted keys, compact, ASCII) of every stored column, including `id` and `prev_hash` in hex.
  - Timestamps are `YYYY-MM-DDTHH:MM:SS.ffffffZ`.
  - Payload enums are stored by value and durations as integer microseconds.
  - `occurred_at` is taken after the lock, so time order follows seq.
- **Partition DDL without migrator credentials:**
  - The worker container has no migrator secret, so create-ahead goes through `audit_create_partition` / `audit_ensure_partitions`, `SECURITY DEFINER` functions owned by `app_migrator` that `app_rw` may execute (creating empty future partitions is harmless).
  - New partitions get `REVOKE ALL ... FROM app_rw`.
  - If an insert finds no partition (SQLSTATE 23514, "no partition"), the writer calls the function and retries once. That is how "the create-ahead job must run at startup too" is met: a long outage can't block auditing.
  - Dropping stays migrator-only. It refuses anything but the oldest past partition, so the chain only ever loses a prefix that the newest anchor bridges.
  - An empty partition's anchor carries the previous anchor forward.
- **Anchors** are protected by the same append-only trigger. `app_rw` gets SELECT only.
- **Verification state lives in the chain:** the incremental start is the latest `audit.verified` event's `through_seq`, so no extra table is needed. Full mode starts from the newest anchor or (0, zeros), and a try-lock prevents concurrent runs. A large chain is read in batches of 5,000 by seq.
- **`VersionStr`:** digits first, with only the pre-release words `alpha|beta|rc|dev|post|build`. That keeps names like `1.0-falcon` out. Model names should be enums.
- **Crons:** `audit_verify` runs daily at 02:30, `audit_partitions` monthly on the 1st at 02:15, and `audit_retention` monthly on the 1st at 03:45 (IST; all settings). Verification runs in the cron callback because at this scale it takes seconds.
- **Own events:** `audit.verified`, `audit.verify_failed` and `audit.partition_dropped` (`app/audit/audit_events.py`).

### Follow-ups

- **Retention in production:** the worker container has no `db_migrator_password` secret, so a real drop would fail (logged as `cron.failed`, with nothing dropped). This first matters in 2031. Mount the secret for the worker, or run retention as a one-shot `migrate`-style service (deploy story).
- **Compliance read path:** the read API and compliance role queries come with 7.x/FR-032. `app_rw` can SELECT the audit; restricting which API roles may read it is an application-level concern.
- **Make check_models a separate CI step:** add `python -m app.audit.check_models` to `make lint` (root Makefile, not owned here). It already runs inside `make test`.
- **Alert subscriber:** admin alerts (later story) should `core.events.subscribe("audit.chain_mismatch", ...)`. Its payload is `seq` and `reason`.
