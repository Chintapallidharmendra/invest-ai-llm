# 7.2: Outputs and watermarked downloads

**Story ID:** 7.2
**Epic:** 7 — Data Lifecycle, Audit & Compliance
**Slug:** outputs-and-watermarked-downloads
**Status:** ready-for-dev

## Story

As a **user**,
I want **generated files stored encrypted and downloadable through short-lived, watermarked links**,
so that **every copy that leaves the system says who took it and when, and links can't be passed around for long**.

## Acceptance Criteria

1. **Migration `7_2_outputs`** creates:
   - `outputs`: `space_id`, `owner_user_id`, `kind` (`xlsx|csv|docx`), `origin` (`operations|table_extract|summary|comparison`), `source_document_ids uuid[]`, `version_of_id`, `title_enc`, `file_path`, `size_bytes`, `ops_log_enc`, `expires_at`, `deleted_at`, timestamps.
   - `download_tokens`: `output_id`, `user_id`, `token_hash`, `expires_at`, `used_count`.

   Both have RLS via `spaces.rls.enable_space_rls`; outputs need **owner AND current membership**.
2. **Service:** `outputs.service.create_output(session, ctx, *, kind, origin, content: AsyncIterable[bytes], title, source_document_ids, version_of_id=None)`:
   - creates the object key (`output`) and streams the file through `crypto.files.encrypt_stream` to `APP_OUTPUTS_FILES_DIR/{space_id}/{output_id}`, written atomically (temp + rename);
   - sets `expires_at` from the space's retention.

   No plaintext file ever touches disk.
3. **Watermark helpers** (`outputs.watermark`) stamp user, timestamp (IST) and workspace code name (or "Private space") onto:
   - XLSX: a `Notes` sheet line + every sheet's footer;
   - DOCX: the footer;
   - CSV: a final `# CONFIDENTIAL …` line.

   They are applied **at download time** to the decrypted stream, for the downloading user.
4. **Links and downloads:**
   - `POST /api/v1/outputs/{id}/download-links` (access-checked) returns `/api/v1/downloads/{token}` once; the token is valid for 24 h and only `sha256` is stored.
   - `GET /api/v1/downloads/{token}` requires a session for **the same user** with current access, then streams decrypt → watermark with `Content-Disposition` and no caching.
   - It records `outputs.downloaded` (kind, size, KeyedHash of the file digest, user).
   - An expired token, another user, or removed access → 404.
5. **Manage:** `GET /api/v1/outputs?space_id=` lists the caller's own outputs with title decrypted. `GET /api/v1/outputs/{id}` returns detail with versions. `DELETE /api/v1/outputs/{id}` shreds the object key, removes the file and deletes the row in one flow, and records `outputs.deleted`.

## Dev Notes

- A removed member also loses access to outputs generated from workspace documents. [Source: prd.md#FR-040]

### Decisions

- **`create_output` takes `space_id`** (keyword): the AC's signature names no space, and an output can't be placed otherwise.
- **`content_hash` column:** the download audit needs "a KeyedHash of the file digest" before any byte is sent (so aborted downloads are audited too). The digest is computed while the file is encrypted at creation and stored as `KeyedHash.of(sha256(plaintext))`: HMAC under the audit key, so it can't be used to confirm a guessed file. The audited size and digest are of the stored file; the watermark differs per download.
- **Download order:** token check, use count and the `outputs.downloaded` row are committed first, then the stream starts. Tokens are multi-use within their 24 h (`used_count` counts uses).
- **In-memory watermarking for XLSX/DOCX:** openpyxl and python-docx need the whole file, and plaintext may not touch disk, so these are decrypted into memory (bounded by `APP_OUTPUTS_MAX_WATERMARK_BYTES`, default 50 MB; over that is 413 `output_too_large`) and stamped in a worker thread. CSV streams chunk by chunk with the line appended at the end.
- **Download tokens** carry `space_id` and use `user_id` as the owner column, with a composite FK to `outputs (id, space_id, owner_user_id)`, so a token can only belong to the output's owner.
- **Watermark text** is ASCII apart from the user's own values (hyphens, not em dashes). IST is a fixed +05:30 offset (no DST, no tz database needed).
- **Files:** `<APP_OUTPUTS_FILES_DIR>/<space_id>/<output_id>`, written to a temp file in the same directory, fsynced and renamed. Paths are checked to stay inside the files directory. Delete removes the file after the transaction commits (the key is already shredded by then).
- **Roles:** only role `user` has outputs. `outputs.created`, `outputs.download_link_issued`, `outputs.downloaded` and `outputs.deleted` are recorded.
