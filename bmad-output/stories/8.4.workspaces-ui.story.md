# 8.4: Workspaces UI

**Story ID:** 8.4
**Epic:** 8 — Workspaces, Isolation & Encryption
**Slug:** workspaces-ui
**Status:** ready-for-dev

## Story

As a **banker**,
I want **to switch between my private space and my deal workspaces, create a workspace, and manage its members**,
so that **my deal team can share documents while everything else stays private**.

## Acceptance Criteria

1. **Current space:** a `SpaceProvider` (mounted once in the app layout for role `user`) exposes `useCurrentSpace()` → `{space, spaces, setSpaceId}` from `GET /api/v1/spaces`.
   - Default is the private space. The choice is remembered per user in `localStorage` (`cs:<user_id>`), and falls back to the private space if that space is gone (removed or closed).
   - Admin and compliance users get no provider and no switcher.
2. **Space switcher** in the header: lists "Private" plus each workspace code name with an "owner" badge; selecting one changes the current space; a "Manage workspaces" link goes to `/workspaces`.
3. **`/workspaces` page:** lists workspaces (code name, my role), and a "New workspace" dialog (`POST /spaces {code_name}`, 1–400 chars) that switches to the new workspace on success.
4. **`/workspaces/:spaceId` page** (owners see controls, members see a read-only member list):
   - Rename (`PATCH /spaces/{id}`).
   - Members: list (`GET …/members`), add by username with role (`POST …/members`; 201 added, 200 role changed), remove (`DELETE …/members/{user_id}`) with confirm. Removing yourself is allowed and returns you to the private space.
   - **Close workspace:** a dialog that requires typing the code name and states "All documents, conversations and outputs in this workspace will be permanently deleted." → `DELETE /spaces/{id}` with `{confirm: true}` → back to the private space.
5. **Errors and access:** a 404 on any workspace call shows "Workspace not found or you no longer have access" and refetches spaces; problem `detail` is shown for 409/422 (e.g. last owner). All mutations invalidate the `spaces` key scope.

## Dev Notes

- **API (done in 8.2/8.3):** `GET /spaces` → `{items: [{id, kind, my_role, code_name}]}` (`code_name` null for the private space); `POST /spaces {code_name}`; `PATCH /spaces/{id} {code_name}`; `DELETE /spaces/{id} {confirm: true}`; `GET/POST /spaces/{id}/members` (`{username, role}`); `DELETE /spaces/{id}/members/{user_id}`. Role change = POST with the new role (200 changed, 201 added). [Source: architecture.md#spaces] [Source: story 8.3 follow-up]
- **FR-040:** only owners (and co-owners) add/remove members; a removed member loses access on the next request; names visible only to members; closing triggers permanent deletion. [Source: prd.md#fr-040-deal-workspaces-with-named-members--should]
- **FR-039:** uploads default to the private space, so the private space is the default current space. [Source: prd.md#fr-039-every-user-has-a-private-space--must]
- **Not accessible → 404** for anything outside the caller's spaces (ADR-023). Membership is re-read per request, so the UI must recover from a 404 by refetching spaces. [Source: architecture.md#adr-023-space-scoped-access-control-and-isolation-supersedes-adr-007]
- **Later consumers:** 9.8 (documents UI) and 3.5 (chat picker) read `useCurrentSpace()`; keep its return type stable and export it from `features/spaces/index.ts`. [Inference]
- **Workspace code names are content** (encrypted at rest); don't log them or put them in URLs — routes use the space ID. [Source: architecture.md#adr-028-envelope-encryption-at-rest-with-per-object-keys-crypto-shredding]
- **Frontend conventions:** TanStack Query, `keyScope("spaces")`, generated types, route auto-discovery. [Source: architecture.md#adr-008-frontend-state-tanstack-query-for-server-state-no-global-store]
- **Retention extension** (`POST /spaces/{id}/retention-extensions`) is 7.3; not in this story. [Source: epics.md#epic-7-data-lifecycle-audit--compliance]

## Testing

- **Approach:** Vitest + Testing Library with mocked fetch; one layout test for the provider mount.
- **Per-AC verification:**
  - AC #1 → default private; stored choice restored; a stored ID no longer in `/spaces` falls back to private; admin has no switcher.
  - AC #2 → switcher lists spaces and changes the current space.
  - AC #3 → create posts the code name and switches to the new space; > 400 chars blocked client-side.
  - AC #4 → member view has no controls; owner adds (201) and changes a role (200); close requires the exact code name; self-removal returns to private.
  - AC #5 → a 404 shows the message and triggers a `/spaces` refetch.
- **Edge cases:** user with no workspaces; two tabs (stale space after close elsewhere → 404 path).
