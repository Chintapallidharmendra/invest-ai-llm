# 9.1: Upload validation and storage

**Story ID:** 9.1
**Epic:** 9 — Document Processing
**Slug:** upload-validation-and-storage
**Status:** ready-for-dev

## Story

As a **banker**,
I want **to upload PDF, Word, PowerPoint, Excel and CSV files into a space, with unsafe files rejected up front**,
so that **my documents are stored encrypted and queued for processing, and nothing dangerous gets near the parser or the model**.

## Acceptance Criteria

1. **Migration `9_1_documents`** (revises `7_2_merge_heads`) creates `documents` with `space_id NOT NULL` + RLS via `enable_space_rls` (shared by all members of the space, no owner column):
   - columns per the data model: `uploader_id`, `kind` (`pdf|docx|pptx|xlsx|csv`), `title_enc`, `filename_enc`, `size_bytes`, `content_hmac`, `page_count`, `slide_count`, `sheet_count`, `status` (`pending|processing|ready|ready_with_warnings|failed|rejected`), `status_code`, `ocr_page_count`, `masked_counts` (jsonb), `flagged_count`, `file_path`, `expires_at`, `deleted_at`, timestamps;
   - unique `(id, space_id)`, and a **composite FK** `conversation_documents(document_id, space_id) → documents(id, space_id)` `ON DELETE CASCADE`.
2. **Validation (pure, `documents/validation.py`), before anything is stored.** Each failure is a 422 problem with a stable `code`:
   - extension + magic bytes agree and the type is supported, else `file_type_unsupported`;
   - size: PDF/DOCX/PPTX ≤ 50 MB, XLSX/CSV ≤ 20 MB, else `file_too_large`; PDF ≤ 300 pages, PPTX ≤ 150 slides, XLSX ≤ 50 sheets (cheap structural counts), else `file_too_large` with `limit`;
   - macro-enabled (macro extension, `vbaProject.bin`, or macro content type) → `macro_file_rejected`;
   - encrypted or password-protected (PDF `/Encrypt`, OLE/CFB `EncryptedPackage` container for OOXML) → `encrypted_file_rejected`;
   - OOXML zip: uncompressed > 500 MB, ratio > 100:1, or > 10,000 entries → `zip_bomb_suspected`.
   No file content, name or detected value is logged or audited, only the code.
3. **`POST /api/v1/spaces/{space_id}/documents`** (multipart, role `user`, caller must be a member, else 404):
   - quotas first: ≤ 50 uploads/day/user (Valkey) → 429 `rate_limited` + `retry_after_s`; ≤ 2 GB active (non-deleted) storage per uploader → 422 `storage_quota_exceeded`; Valkey down → 503 `rate_limit_unavailable`;
   - **duplicate:** `content_hmac` = HMAC-SHA256 of the bytes under a key derived from the space key; a match in the same space → 409 `duplicate_document` + `existing_document_id` (the "use existing" offer);
   - otherwise, in one transaction: insert the row (`pending`, `expires_at = now + spaces.retention_days`), create the `document` object key, encrypt title/filename, write the original as a chunked encrypted file at `/data/files/{space_id}/{document_id}`, and `enqueue("ingest", {document_id}, user_id, space_id)`;
   - → **202** with the document resource.
4. **Read and delete:**
   - `GET /api/v1/spaces/{space_id}/documents` (members; newest first; cursor; decrypted title, kind, status, counts, size, `expires_at`);
   - `GET /api/v1/documents/{id}` (status, `status_code`, counts, expiry);
   - `DELETE /api/v1/documents/{id}` → 204: shreds the object key, deletes the row (children cascade) and removes the file (FR-053). Any member may delete. Not accessible → 404.
5. **Selected-set resolver:** `chat.selected_set` now resolves through `documents.service.unusable_ids(session, ctx, space_id, ids)`, which returns the IDs that are not in that space, not visible, deleted or not `ready`/`ready_with_warnings`. The `ingest` job type is registered (payload `{document_id}`), with a handler that delegates to `documents.ingestion.run` (a stub here that fails the job with `ingestion_unavailable`; 9.4 replaces it).
6. **Audit and deploy:** audit `documents.uploaded` (IDs, kind, size bucket), `documents.upload_rejected` (code only), `documents.deleted`. `deploy/compose.yml` mounts `${APP_DATA_DIR:-/data}/files` read-write on `api` and `worker`, the staged models directory read-only at `/models` on both, and a `tmpfs` at `/tmp` on `api` (multipart spooling).

## Dev Notes

- **Pipeline step 1 (validate):** extension + magic bytes; size and page/slide/sheet limits; reject macro-enabled (`vbaProject.bin` or macro extension), encrypted/password-protected, and zip bombs (> 500 MB uncompressed, ratio > 100:1, > 10,000 entries); encrypt the original with the object key; `status=pending`. [Source: architecture.md#adr-027-document-ingestion-pipeline-supersedes-adr-014]
- **FR-042 limits:** PDF/DOCX ≤ 300 pages and ≤ 50 MB; PPTX ≤ 150 slides; XLSX/CSV ≤ 20 MB, ≤ 50 sheets, ≤ 500k rows/sheet (rows and DOCX pages are checked by the parser in 9.4); duplicates offered as "use existing". [Source: prd.md#fr-042-upload-documents--must]
- **Problem codes:** `file_type_unsupported`, `macro_file_rejected`, `encrypted_file_rejected`, `file_too_large`, `zip_bomb_suspected`, `not_ready`; 202 + resource for async work. [Source: architecture.md#adr-003-response-error-and-sse-event-conventions] [Source: architecture.md#adr-002-restjson-under-apiv1--sse-for-chat-streaming]
- **Data model:** `documents` columns as listed; `content_hmac` is for duplicate detection within the space. [Source: architecture.md#documents--sheets]
- **Encryption:** original files, document titles and file names are encrypted; files in 1 MB chunks; AAD binds space, object and field. Only `crypto` imports `cryptography`, hence `crypto/mac.py`. [Source: architecture.md#adr-028-envelope-encryption-at-rest-with-per-object-keys-crypto-shredding]
- **Files:** `/data/files/{space_id}/{object_id}`; temp files only on tmpfs; `/mnt` never holds content. [Source: architecture.md#storage-strategy] [Source: architecture.md#adr-028-envelope-encryption-at-rest-with-per-object-keys-crypto-shredding]
- **Quotas (FR-037):** 50 uploads/day, 2 GB active storage per user; clear messages; events audited. They live here (not in 4.2) because this story owns the upload endpoint. Values are env settings (`APP_DOCUMENTS_*`) until an admin settings screen exists. [Source: prd.md#fr-037-per-user-rate-limits-and-upload-quotas--should] [Inference]
- **Valkey fails closed** (no content stored there). [Source: architecture.md#adr-018-valkey-for-rate-limits-upstream-token-buckets-and-short-lived-cache]
- **Isolation:** RLS on `documents`; repository functions take `AccessContext`; 404 when not accessible; membership re-read per request. [Source: architecture.md#adr-023-space-scoped-access-control-and-isolation-supersedes-adr-007]
- **Jobs:** the payload holds IDs only; enqueue in the same transaction as the row (`enqueue(..., session=tx)`). [Source: architecture.md#adr-017-background-jobs-worker-process-apscheduler--postgres-job-table]
- **Import rules:** `documents` may not import `app.chat` or fastapi (except `documents.routes`, already ignored in `.importlinter`). So the resolver is wired from the chat side: `chat/selected_set.py` imports `documents.service.unusable_ids` as its default resolver (keep `register_resolver` for tests). [Source: backend/.importlinter]
- **Not here:** moves (`POST /documents/{id}/moves`) need re-encryption under the target space (AAD contains `space_id`) and belong with 9.8; the report endpoint is 9.5; the viewer is 9.7. [Inference]

## Testing

- **Approach:** unit tests for validation on crafted byte fixtures; API + DB tests with `pg`, fake Valkey and a temp files dir; users A and B in a workspace, outsider C.
- **Per-AC verification:**
  - AC #1 → C sees 0 rows via API and raw SQL under C's context; no context → 0 rows; a `conversation_documents` row pointing at another space's document is rejected by the FK.
  - AC #2 → fixtures: `.xlsm`, `.docx` with `vbaProject.bin`, password-protected DOCX (CFB) and PDF, PNG renamed `.pdf`, 600 MB-expanding zip, 10,001-entry zip, 301-page PDF, 151-slide PPTX → each code; captured logs contain no file name.
  - AC #3 → happy path returns 202 `pending`, file on disk is ciphertext (no planted canary string), one `ingest` job queued with `{document_id}` only; duplicate → 409 with the existing ID; 51st upload → 429; over 2 GB → 422; Valkey down → 503.
  - AC #4 → list order and pagination; delete removes row, file and key (`KeyDestroyed` on the old title ciphertext); C gets 404 on get/delete.
  - AC #5 → `PUT /conversations/{id}/documents` accepts a `ready` document in the space and rejects `pending`, other-space and deleted ones with 422.
  - AC #6 → `assert_no_content` on audit rows; compose config test checks the mounts and tmpfs.
- **Edge cases:** upload to a closed workspace (404); same file in two spaces (not a duplicate); zero-byte file (`file_type_unsupported`); CSV with BOM.

## Learnings from Previous Stories

- **3.1:** the resolver contract is `unusable(session, ctx, space_id, ids) -> ids`; until now only an empty set was accepted. Composite FKs `(…, space_id)` are how "same space" is enforced.
- **7.2:** `outputs/storage.py` is the pattern for encrypted files (chunked `crypto.files.encrypt_stream`, write to a temp name then rename, remove on rollback). Orphan files from a crash need the 7.4 sweep; don't add one here.
- **8.2:** `enable_space_rls(op, "documents")` in upgrade, `disable_space_rls` in downgrade.
- **8.1:** `create_object_key(tx, space_id, "document", id)`; `shred_object(tx, "document", id)`.
- **2.2:** `auth.ratelimit.hit(scope, subject, limit=, window_s=)` raises `RateLimitUnavailableError` when Valkey is down.
- **9.2:** the parser enforces rows-per-sheet and DOCX pages; don't duplicate a full parse in the API.
