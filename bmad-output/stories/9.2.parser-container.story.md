# 9.2: Parser container

**Story ID:** 9.2
**Epic:** 9 — Document Processing
**Slug:** parser-container
**Status:** ready-for-dev

## Story

As the **builder**,
I want **untrusted files parsed in a locked-down container that returns structured text and tables with locators**,
so that **a hostile file can at worst crash a sandbox, and every extracted fact keeps its page, slide or cell reference**.

## Acceptance Criteria

1. **Service:** the `parser` container exposes `POST /parse` (multipart: the file + `kind` + limits) and `GET /healthz` on the internal `parsing` network only. It holds no DB credentials and no app secrets, and has no route out.
2. **PDF / DOCX / PPTX** via Docling (offline artifacts from `/models`, `DOCLING_ARTIFACTS_PATH`) return:
   - text items with `locator` (page or slide), `kind` (`text|heading|note|comment|metadata`) and reading order;
   - tables with cells (row, col, spans, text), caption and locator.

   Pages without a text layer are flagged `needs_ocr` (OCR itself is 9.3).
3. **XLSX** via openpyxl (`read_only=True, data_only=True`) returns, per sheet:
   - name and cell values, with numbers as numbers and dates as ISO strings;
   - comments;
   - a formula-without-cached-value count, from a second pass with `data_only=False`.

   External links are never followed and nothing is evaluated. **CSV** goes through Polars with encoding sniffing (UTF-8/UTF-16/cp1252).
4. **Limits and errors:**
   - Enforced: PDF/DOCX ≤ 300 pages, PPTX ≤ 150 slides, XLSX ≤ 50 sheets and ≤ 500k rows per sheet.
   - Each request is parsed in a **child process** with `setrlimit` (CPU 120 s, address space 3 GB) and a wall timeout.
   - Breaches and corrupt files return typed error codes (`limit_exceeded`, `corrupt_file`, `timeout`, `unsupported`), never a crash of the service.
5. **Container hardening (`deploy/compose.parser.yml`):** `read_only`, tmpfs `/tmp`, `cap_drop: ALL`, `no-new-privileges`, `mem_limit: 4g`, a pids limit, a non-root user, the `parsing` network only (internal), and models mounted read-only. A shared Pydantic result schema (`parser/app/schema.py`) is versioned (`schema_version`).

## Dev Notes

- **Parser container:** no network, CPU and memory limits (4 GB), read-only root, tmpfs scratch; the worker sends decrypted bytes over an internal socket and receives a structured result. Docling for PDF/DOCX/PPTX (text with provenance, headings, tables via TableFormer, notes, comments, metadata); openpyxl `read_only=True, data_only=True` (cached values only, no formula evaluation, external links ignored, comments captured); CSV via Polars with encoding sniffing. [Source: architecture.md#ADR-027]
- **LOCKED:** unmasked text never leaves the parser → worker boundary except into the encrypted original; only `documents.ingestion` calls the parser. [Source: architecture.md#ADR-027]
- **Limits (FR-042):** PDF/DOCX ≤ 300 pages and ≤ 50 MB; PPTX ≤ 150 slides; XLSX/CSV ≤ 20 MB, ≤ 50 sheets, ≤ 500k rows per sheet. [Source: prd.md#FR-042]
- **NFR-025:** parsers run with resource limits and no network; malformed or zip-bomb files are rejected without affecting other users. [Source: prd.md#NFR-025]
- Offline bundles: Docling layout/TableFormer and RapidOCR models are pre-staged under `/models`. [Source: architecture.md#ADR-034]
- The parser's dependencies are already declared and locked (`parser/pyproject.toml`, `uv.lock`); don't edit them. [Source: parser/README.md]
- The parser never logs content: log counts, durations and error codes only. [Source: architecture.md#ADR-033]

## Testing

- **Approach:** tests in `parser/tests/` run the parse functions directly and through the HTTP app, using the synthetic corpus (1.7) and generated hostile samples.
- **Per-AC verification:**
  - AC #1 → health 200; no environment variables with secrets; the compose config shows only the `parsing` network.
  - AC #2 → corpus PDF/DOCX/PPTX locators match the manifest's planted facts (page/slide); a table's cells match; an image-only page → `needs_ocr`.
  - AC #3 → cached values returned; a formula without cache counted; an external link ignored; CSV encodings.
  - AC #4 → a 301-page PDF → `limit_exceeded`; an infinite-loop/huge file → `timeout` while the service still answers `/healthz`.
  - AC #5 → `docker compose config` assertions (in a test that runs only when Docker is present).
- **Edge cases:** an empty file; a renamed extension (the magic check is 9.1's, but the parser still fails cleanly); deeply nested DOCX tables.
