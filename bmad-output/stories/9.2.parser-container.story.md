# 9.2: Parser container

**Story ID:** 9.2
**Epic:** 9 — Document Processing
**Slug:** parser-container
**Status:** ready-for-dev

## Story

As the **builder**,
I want **untrusted files parsed in a locked-down container that returns structured text and tables with locators**,
so that **a hostile file can at worst crash a sandbox, and every extracted fact keeps its page, slide or cell reference**.

## Acceptance Criteria

1. **Service:** the `parser` container exposes `POST /parse` (multipart: the file + `kind` + limits) and `GET /healthz` on the internal `parsing` network only. It holds no DB credentials and no app secrets, and has no route out.
2. **PDF / DOCX / PPTX** via Docling (offline artifacts from `/models`, `DOCLING_ARTIFACTS_PATH`) return:
   - text items with `locator` (page or slide), `kind` (`text|heading|note|comment|metadata`) and reading order;
   - tables with cells (row, col, spans, text), caption and locator.

   Pages without a text layer are flagged `needs_ocr` (OCR itself is 9.3).
3. **XLSX** via openpyxl (`read_only=True, data_only=True`) returns, per sheet:
   - name and cell values, with numbers as numbers and dates as ISO strings;
   - comments;
   - a formula-without-cached-value count, from a second pass with `data_only=False`.

   External links are never followed and nothing is evaluated. **CSV** goes through Polars with encoding sniffing (UTF-8/UTF-16/cp1252).
4. **Limits and errors:**
   - Enforced: PDF/DOCX ≤ 300 pages, PPTX ≤ 150 slides, XLSX ≤ 50 sheets and ≤ 500k rows per sheet.
   - Each request is parsed in a **child process** with `setrlimit` (CPU 120 s, address space 3 GB) and a wall timeout.
   - Breaches and corrupt files return typed error codes (`limit_exceeded`, `corrupt_file`, `timeout`, `unsupported`), never a crash of the service.
5. **Container hardening (`deploy/compose.parser.yml`):** `read_only`, tmpfs `/tmp`, `cap_drop: ALL`, `no-new-privileges`, `mem_limit: 4g`, a pids limit, a non-root user, the `parsing` network only (internal), and models mounted read-only. A shared Pydantic result schema (`parser/app/schema.py`) is versioned (`schema_version`).

### Decisions

- **Stdlib HTTP server** (`ThreadingHTTPServer` + `email` multipart parsing): the locked dependencies have no ASGI server, and the story forbids editing them.
- **Sandbox:** each request runs in a child process from a `forkserver`. Before reading the file the child sets `RLIMIT_CPU` 120 s, `RLIMIT_AS` 3 GB and no core dumps, and it returns JSON over a pipe. The parent kills it at the wall limit (180 s default). At most `PARSER_CONCURRENCY` (2) parses run at once. CPU and wall kills are `timeout`, `MemoryError` is `limit_exceeded`, and any other death or exception is `corrupt_file`.
- **Docling is imported in each child, not preloaded in the forkserver:** forking after torch was imported crashed children on macOS (SIGSEGV), so the forkserver preloads only the light modules. That costs a few seconds per PDF/DOCX/PPTX request.
- **Locators** follow the corpus convention (`evals/corpus/generate/manifest_schema.py`): `p.N`, `slide N`, `slide N notes`, `para N` (1-based body paragraph), `table T`, `comment N`, `meta:<property>`; XLSX `rows` carry the sheet row number. Docling has no page provenance for DOCX, so DOCX text is matched in order to python-docx body paragraphs.
- **Docling does structure; its own dependencies fill gaps:** pypdfium2 (page count before conversion, `needs_ocr`, PDF metadata), python-docx (paragraph locators, comments, core properties, page count from `docProps/app.xml` or explicit/rendered page breaks), python-pptx (slide count before conversion, notes, core properties). XLSX comments are read from the package's comments parts, because openpyxl's read-only mode has none.
- **CSV values stay strings** (no type inference), and NUL bytes mean `corrupt_file` (binary data).
- **Models:** the PDF pipeline needs exactly two Hugging Face repos, both now in `deploy/models/manifest.yaml` with per-file size and SHA-256:
  - `docling-layout-heron` @ `8f39ad3c…`;
  - `docling-models` @ tag `v2.3.0` = `fc0f2d45…` (TableFormer accurate + fast).

  They're named `docling-project--…`, the folder names Docling expects under `DOCLING_ARTIFACTS_PATH`. Each is mounted read-only at `/models/docling/<name>`. `stage-models.sh` verified and installed both, and all tests pass against only those files.

### Follow-ups

- **Image size:** on Linux the locked torch pulls the CUDA wheels (nvidia-*), so the CPU-only parser image is several GB. A CPU-only torch index in `parser/pyproject.toml`/`uv.lock` would shrink it, but that's a dependency change for its own story.
- **CPU budget:** the 60-page CIM takes ~28 s wall on the dev Mac. `RLIMIT_CPU` counts every thread, so measure a 300-page PDF on the UAT VM with `OMP_NUM_THREADS=4`; if it exceeds 120 s CPU, lower the threads or adjust the limit.
