# 9.4: Ingestion orchestration and storage

**Story ID:** 9.4
**Epic:** 9 — Document Processing
**Slug:** ingestion-orchestration-and-storage
**Status:** ready-for-dev

## Story

As a **banker**,
I want **an uploaded document to be parsed, OCR'd where needed, and stored as encrypted segments and tables, with a clear final status**,
so that **I know when it's ready, and a crash or restart never leaves a half-processed document marked ready**.

## Acceptance Criteria

1. **Migration `9_4_segments`** (revises `9_1_documents`) creates, each with `space_id NOT NULL` + `enable_space_rls` and a composite FK `(document_id, space_id) → documents(id, space_id) ON DELETE CASCADE`:
   - `doc_segments` (`document_id`, `seq`, `locator`, `kind` `text|heading|note|comment|metadata`, `text_enc`, `ocr`, `flagged`), unique `(document_id, seq)`;
   - `doc_tables` (`document_id`, `table_index`, `locator`, `n_rows`, `n_cols`, `cells_enc`, `caption_enc`), unique `(document_id, table_index)`.
2. **Parser client (`ingestion/client.py`):** `parse(kind, data)` → `POST {APP_DOCUMENTS_PARSER_URL}/parse`; `ocr(data, pages)` → `POST /ocr` in batches of ≤ 20 pages. Responses are validated against backend mirrors of `ParseResult` / `OcrResult` / `ParseFailure` (`schema_version == 1`, else permanent failure `parser_schema_mismatch`). Connection errors and 5xx are retryable `JobError`s; a `ParseFailure` is permanent.
3. **Segment processor contract (`ingestion/processing.py`):** `SegmentProcessor` protocol `process(items) → ProcessedItems` (masked text per item, `flagged` flags, `masked_counts`, `flagged_count`) for text items and table cells, with `register_processor()`. **Only processed text is ever stored.** With no processor registered, the job fails the document with `masking_unavailable` (fail closed); 9.5 registers the real one.
4. **The `ingest` job (`ingestion/__init__.run`)**, for `{document_id}`:
   - sets the job's RLS context from `user_id` + `space_id` (re-reading memberships; uploader no longer a member → `failed`/`not_accessible`); sets `processing`;
   - decrypts the original in memory, calls `/parse`; `limit_exceeded` / `unsupported` / `corrupt_file` → `rejected` or `failed` with the parser's code as `status_code`;
   - processes and stores text segments and tables in one transaction; then OCR batches for `needs_ocr` pages, each batch processed and committed with `ocr=true` (**resumable**: pages already stored are skipped on retry);
   - finishes in one transaction: counts (`page_count`, `slide_count`, `sheet_count`, `ocr_page_count`, `masked_counts`, `flagged_count`), `status = ready` or `ready_with_warnings` (any OCR page, flagged segment, or page without text), then emits the core event `documents.ingestion_finished(document_id, space_id, user_id, status)`.
   - Never `ready` unless every step committed. Re-running a finished document is a no-op.
5. **Post-ingest steps:** `register_post_step(name, fn)` lets later stories (9.6 chunks/index, 10.1 sheets) run inside the job before the final transaction, in registration order; a failing step fails the document.
6. **Logs, audit, metrics:** `documents.ingested` / `documents.ingest_failed` audit events (IDs, kind, status, code, counts); logs carry counts and timings only. No segment text, file name or title in logs, spans, audit or job rows.

## Dev Notes

- **ADR-027 sequence:** upload → worker job → parser (Docling / OCR / openpyxl) → worker: injection scan → mask → chunk/tables/sheets → encrypt + index → `ready` + report + notification. Failures → `failed` with a reason code. Idempotent and resumable. **Unmasked text never leaves the parser → worker boundary except into the encrypted original;** indexes, prompts, logs and traces only see masked text; only `documents.ingestion` calls the parser. [Source: architecture.md#adr-027-document-ingestion-pipeline-supersedes-adr-014]
- **Data model:** `doc_segments` (`locator`, `kind`, `text_enc` masked, `ocr`, `flagged`) and `doc_tables` (`locator`, `table_index`, `n_rows`, `n_cols`, `cells_enc` masked, `caption_enc`). Chunks are 9.6, sheets 10.1, the report 9.5. [Source: architecture.md#documents--sheets]
- **Encryption:** segment and table text under the document's object key, AAD per row (`segment_<seq>`, `table_<index>_cells`, `table_<index>_caption`). [Source: architecture.md#adr-028-envelope-encryption-at-rest-with-per-object-keys-crypto-shredding]
- **Jobs:** background jobs carry `user_id` + `space_id` and set the same RLS context before touching data; max 3 attempts with backoff; payload IDs only. [Source: architecture.md#adr-023-space-scoped-access-control-and-isolation-supersedes-adr-007] [Source: architecture.md#adr-017-background-jobs-worker-process-apscheduler--postgres-job-table]
- **NFR-013:** jobs resume or fail cleanly after a restart; no half-processed document is marked ready. **NFR-024:** a 50-page text PDF ready in ≤ 2 min. [Source: prd.md#nfr-013-fail-safe-degradation--must-reliability] [Source: prd.md#nfr-024-processing-performance--should-performance]
- **FR-042:** each upload ends ready, ready with warnings, or failed with a reason. [Source: prd.md#fr-042-upload-documents--must]
- **Why a processor contract:** masking and the injection scan are 9.5 (wave 8). Storing unmasked text in between would break ADR-027, so without a processor the job fails closed. [Inference]
- **Notifications:** the in-app notifications table and API don't exist yet; this story only emits `documents.ingestion_finished` through `core.events`. A new story **9.15 notifications-api** subscribes to it (and to summary/comparison completion). [Inference; logged in decision-log]
- **Parser contract:** 200 `ParseResult`, 422 `ParseFailure`, `schema_version == 1`; 9.3 adds `TextItem.ocr`, `needs_ocr` cap and `/ocr` (`OcrResult`). [Source: story 9.2 follow-up] [Source: story 9.3]

## Testing

- **Approach:** worker-level tests calling `run()` with `pg`, a temp files dir, a fake parser (an `httpx.MockTransport` replaying recorded responses from the real parser on the 1.7 corpus), and a fake processor that masks a planted PAN.
- **Per-AC verification:**
  - AC #1 → RLS: an outsider sees 0 segments/tables; deleting the document cascades.
  - AC #2 → schema version 2 → permanent `parser_schema_mismatch`; 503 → retry then `failed`/`parser_unavailable` after 3 attempts.
  - AC #3 → without a processor → `failed`/`masking_unavailable` and 0 segment rows; with the fake one, stored ciphertext decrypts to masked text and the raw PAN appears nowhere in the DB (byte scan).
  - AC #4 → happy PDF → `ready` with counts; scanned pages → `ready_with_warnings`, `ocr=true`; kill after the first OCR batch (raise in the second) → retry skips stored pages and finishes; parser `limit_exceeded` → `rejected`; re-run of a `ready` document does nothing.
  - AC #5 → a registered post-step runs before the final transaction; a raising one fails the document.
  - AC #6 → `assert_no_content` on audit rows; captured logs free of planted text and file names.
- **Edge cases:** document deleted while the job runs (job ends quietly); uploader removed from the workspace; empty PDF (0 text items → `ready_with_warnings`).

## Learnings from Previous Stories

- **9.2:** POST multipart to `http://parser:8080/parse`; check `schema_version == 1`; `detail` is a fixed word.
- **1.11:** raise `PermanentJobError` for non-retryable failures; `JobContext.progress(done, total)` updates `jobs.progress` (use it for OCR batches).
- **9.1:** the original is at `/data/files/{space_id}/{document_id}`, encrypted under `("document", id)`; read it with `documents.storage`.
- **8.1:** key lookups are cached for 5 minutes; decrypting many segments under one key is cheap.
- **alembic env** imports only `app/<module>/models.py`, so `models_ingestion.py` must be imported from `documents/models.py`.
